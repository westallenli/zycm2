# 已知测试差异（2026-10-20 记录）

## 结论先说

- **快速自检（`快速自检.bat`）是可信门禁**：编译零错误 + 206 用例全绿。
- **全量自检（`自检.bat`）会红**，原因不是功能坏了，而是下面这些旧测试仍在断言
  **已经变更的权限模型与旧界面**。

## 差异来源

| 类别 | 具体变化 | 受影响测试 |
|---|---|---|
| 权限模型 | 副总指挥只能在**事件启动后**任命；事件进行中的名册写入须走人员管理入口 | `tests/test_p16_*.py`、`tests/test_upgrade_material*.py` |
| 界面改版 | 沙盘改为浮动版（`cmd-*`），旧 `sop-*` 区块与"六问"标题已移除 | `tests/test_upgrade_sop*.py`（已加 skip 说明） |
| 页壳改版 | 子页不再输出 `data-module` 标记 | `tests/test_upgrade_unified_framework.py`（已 skip 1 条） |
| 环节页改版 | 只读页不再固定输出表单；依据选择器改为预置字段 | `tests/test_upgrade_nine_flow.py`（已 skip 2 条） |

## 已做过的处理

1. 明确属于旧界面的断言：用 `@unittest.skip('原因')` 标注，**不静默通过**。
2. 需要新界面保护的：新增 `test_upgrade_sop_ui_v2.py`、`test_upgrade_nine_flow_ui_v2.py`，
   按现在的界面重新约定。
3. 测试夹具向现实流程靠拢：`tests/personnel_support.py` 现在会先启动事件再任命副指挥。

## 仍然红的（未处理）

约 100+ 条，集中在 `test_p16_*.py` 与 `test_upgrade_material*.py`。
它们编码的是旧权限模型下的调用顺序，逐层修会不断暴露下一层断言差异，因此
**本轮停止逐条修补**，记录在此，等待按现行权限模型整组重写。

## 重写时请注意

- 事件必须先 `start`，再 `handle_deputy_appointment`。
- 名册类基础信息走人员管理入口；事件内编组仍须副指挥长具名。
- 沙盘断言请对着 `cmd-*` 结构写，不要再锚定 `sop-*`。

## 不要做的事

- 不要为了让红灯消失而删掉断言。
- 不要把 `skip` 当成通过——报告里的 `skipped=N` 必须能对上原因。
