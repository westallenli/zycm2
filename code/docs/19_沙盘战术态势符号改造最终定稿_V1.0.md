# P19 沙盘战术态势符号改造最终定稿

> 版本：V1.1
> 日期：2026-08-27
> 适用工作区：`D:/熊猫开发项目/熊猫智脑cola v4`
> 对应页面：`/sand`
> 文档性质：P19 最终方案定稿，作为后续实施、测试和验收依据。
> 当前状态：方案已修订并进入实施；实施现状见 §14.1（2026-08-28 首批）。

## 1. 定稿结论

P19 将沙盘从通用点、线、面标注页改为消防应急战术态势图。地图是指挥主画面，业务对象必须通过形状、颜色、线型、透明度、纹理和中文标签共同表达。前台只显示业务事实、判断、建议、命令、回执和待决断事项，不显示模型、Agent、推理过程或后台运行状态。

首版固定为：

```text
P0 核心对象类型：15 类
首版演示对象实例：23 个，其中 22 个地图对象和 1 个隔火带缺口子记录
P1 按需对象类型：10 类
主要业务图层：6 组，渲染层 12 层
标绘状态：草稿、待核验、已核验、已发布、已撤回
路线状态、命令状态、冲突状态分别独立管理
正式改变路径：司令决断 → 命令确认 → 执行单位接收 → 条件确认 → 开始执行 → 回执 → 独立核验
```

本定稿不再增加新的首版对象类型、冲突等级或超时分支。后续新增内容必须进入 P2 变更评审。

## 2. 目标、边界和红线

### 2.1 首版目标

首屏必须让司令直接看懂：

```text
火场范围、当前火线、蔓延方向、隔火带、小队位置和路线、指挥保障、无人机证据、重点保护目标
```

司令可以在地图上查看对象、绘制对象、保存草稿、提交核验、确认发布、撤回正式对象，查看路线冲突、命令状态、执行回执和四级待决断事项。

### 2.2 首版不做

以下能力不进入 P19 首版：

- 实时北斗定位和实时队伍轨迹；
- 无人机实时视频、电量、高度、链路质量；
- 自动识别火线、热点或危险区；
- 自动规划、自动改道或自动生成精确隔火带；
- 自动地形、气象、水文、道路和通信分析；
- 三维地形、复杂 GeoTIFF 分析和多事件联动；
- 通过图层联动自动发布对象、改写火线、改变命令或移动队伍。

### 2.3 工程红线

```text
AdvisorProposal → GeneralDecision → ExecutionOrder → Policy/Approval → Executor
```

- `workspace.append_event` 是哈希审计链唯一写入口；
- 参谋建议不等于司令决断，方案采纳不等于命令下达，执行回执不等于独立核验；
- `geo_points` 是真实地图权威坐标，旧 `points` 只作兼容，不得猜测上图；
- 影像、候选、草稿、方案推演不能静默改写已发布正式态势；
- 没有来源的数据显示“待核实”，不显示编造的 0、人数、水量、库存、风速或实时位置；
- 演示数据、近似坐标、模拟回执和待接入接口必须明确标识；
- 所有创建、编辑、核验、发布、撤回、命令、回执和关闭动作都必须经过权限校验并写入审计链。

- 无人机位置和影像覆盖区必须是两个对象；

## 5. 数据结构和字段规则

### 5.1 对象结构

标绘对象统一分为五部分：

```text
对象身份 + 几何位置 + 战术语义 + 业务属性 + 核验审计信息
```

兼容字段保留：

```text
annotation_id、event_id、kind、geometry、geo_points、points、title、status、certainty、source、created_by、created_at、updated_at、valid_from、valid_until、responsible_unit、responsible_person、related_goal_id、related_plan_id、related_order_id、image_id、map_version、note
```

新增或强化字段：

```text
layer、source_ref、basis、details、version、supersedes_id、withdraw_reason、verification_record、publication_record
```

约束：

- `kind` 必须为注册对象类型；
- `geometry` 只能是 `point`、`line`、`polygon`；
- `geo_points` 是真实地图唯一权威位置；
- `points` 仅用于旧示意图兼容；
- 关键业务属性必须进入 `details`，不能继续塞进 `note`；
- 标题去空格后 1 至 40 字，备注最长 500 字；
- 不能由前端直接提交可信的创建人、发布时间、核验人或发布人。

### 5.2 通用字段分层

对象详情分为：

**事实**：来源、位置、采集时间、报告人、实际宽度、实际状态。

**判断**：风险等级、蔓延方向、影响对象、处置优先级、研判依据。

**业务动作**：责任单位、责任人、关联小队、方案、命令、计划时间、完成状态。

页面必须分栏显示，不能把事实、判断、建议和命令合成一句话。

### 5.3 受控字段和演示标识

以下字段使用内部受控值，并由统一展示映射转换为中文：

```text
kind：注册表中的 15 类 P0 类型、10 类 P1 类型
geometry：point、line、polygon
annotation_status：draft、pending_review、verified、published、withdrawn
route_status：proposed、pending_check、confirmed、restricted、closed、completed
conflict_level：notice、review、blocked、decision
source_type：现场报告、无人机影像、卫星热点、人工标绘、外部报警、系统导入、后台候选
layer_group：火情态势、防控作业、兵力行动、指挥保障、风险环境、证据影像
positioning_status：已定位、人工粗略覆盖、未配准
```

接口和数据库可以保留英文枚举，前台不得显示内部值。`is_demo`、`demo_notice` 和 `position_label` 为演示标识字段；演示对象必须为 `is_demo=true`，`demo_notice` 固定包含“演示数据、非现场实时数据”，地图坐标详情显示“演示近似位置”。

`basis` 为字符串数组，至少记录来源说明；`source_ref` 为来源编号数组；`verification_record` 和 `publication_record` 为记录对象，至少包含操作人、时间、结论和依据。`details` 为按 `kind` 校验的对象，缺失专属字段时只能保存草稿。

旧对象映射：旧火点映射为火点/热点，旧火线映射为当前重点火线，旧隔离带映射为隔火带，旧路线按其来源映射为小队路线或撤离路线，旧资源点按详情映射为水源地、物资保障点、医疗救护点或指挥部。无法安全映射的旧对象保留原类型并进入待人工归类，不得自动发布新战术语义。

| 类型 | 必备字段和规则 |

| 火场范围 | `basis`、观测时间、范围状态、最后核验时间；面至少 3 点，发布需依据和核验记录 |

### 5.5 统一校验顺序

```text
请求格式
→ 对象类型
→ 几何合法性
→ 必填字段
→ 取值范围
→ 来源和时间
→ 关联对象
→ 当前状态和版本
→ 权限
→ workspace.append_event
→ 页面刷新
```

失败即 fail-closed，不写业务成功状态，不写伪造成功审计。

坐标和几何基准固定为：`geo_points` 使用 `[纬度, 经度]` 顺序，坐标参考按现有地图服务统一处理；距离阈值使用米制地表距离计算。面对象由服务端校验闭合、非自相交、非零面积和至少 3 个不同顶点，服务端可补闭合首点但不得补造缺失顶点；线对象至少 2 个不同节点，点对象只能有 1 个有效坐标。版本提交必须携带 `base_version`，版本不一致时拒绝提交并要求重新加载。

### 5.6 冲突记录和演示依赖

冲突记录独立于标绘对象，至少包含：`conflict_id`、`event_id`、`route_id`、`route_version`、`trigger_annotation_id`、`conflict_level`、`relation`、`detected_at`、`status`、`evidence_refs`、`decision_id`、`handled_by`、`handled_at` 和 `resolution_reason`。同一事件、路线版本、触发对象版本和冲突类型只允许一条未关闭记录。

同一路线命中多个冲突时，最终等级按四级决断、三级阻断、二级复核、一级提示从高到低取最高级；所有命中关系仍保留在明细中。单条路线三级阻断只有在它是任务的唯一可用路径、或与其他路线和保障事实共同造成行动不足时，才升级为任务级四级决断，不能把单条阻断自动等同于四级决断。

演示场景除 22 个地图对象和 W-03 缺口子记录外，必须提供至少 1 个命令、1 条命令接收记录、1 条执行回执、1 条独立核验记录和 1 个来源记录夹具。它们不计入 23 个地图对象，但必须能由演示数据库和测试种子完整重建。

## 6. 状态机、权限和版本

### 6.1 标绘对象状态

标绘对象的 `annotation_status` 只有以下五种：

```text
草稿 → 待核验 → 已核验 → 已发布 → 已撤回
```

驳回路径：

```text
待核验 → 草稿
```

以下不是标绘对象状态，而是独立字段或叠加结果：

```text
路线状态：route_status
冲突状态：conflict_level
时效状态：freshness_status，正常、需要复核、已失效
计划语义：details.route_type 或 details.belt_status
执行状态：关联命令和回执状态
```

“已核验未发布”表示 `annotation_status=verified` 且不存在有效发布时间，不新增状态。“需要复核”由时效或联动计算产生，不改变标绘状态；“已失效”由 `freshness_status` 表示，不等同于撤回。公共屏只显示 `annotation_status=published`、当前有效且未撤回的对象。

禁止：

```text
草稿 → 已发布
待核验 → 已发布
已撤回 → 已发布
已发布 → 草稿
```

已发布对象修改时必须建立修订草稿，原版本保留历史。几何、风险等级、路线起终点、责任单位、关联命令等关键字段变化必须重新核验。

### 6.2 命令和回执关键状态

命令主状态固定为：

```text
草稿 → 待校验 → 待审批 → 待确认 → 已确认待接收 → 已接收待开始 → 执行中 → 部分完成 → 已完成待核验 → 已关闭
```

命令确认、执行单位接收、执行条件确认和开始执行是独立事件。`已接收待开始` 表示执行单位已经接收但尚未确认开始，条件确认记录作为命令状态进入执行中的前置条件。

命令必须有 `task_level`，取值为“紧急、高风险、普通”，由司令或授权确认人在命令确认前设置；修改任务等级必须建立新版本并重新计算接收和回执时限。命令送达记录至少包含发送时间、送达时间、查看时间、接收时间和接收人，无法证明送达时不得把“已发送”当作“已接收”。

版本和并发：命令或路线提交必须携带 `base_version`；版本已变化时拒绝旧页面提交，不能覆盖新版本。重发不重置原超时历史，不延长有效期。

异常和控制状态作为命令的独立 `command_control_state`，不覆盖主状态：

```text
正常、接收逾期、暂停、撤回通知已发送、等待停止确认、撤回执行中、待替代、执行异常、无法核验、异常关闭
```

回执作为独立记录，至少包含命令编号、命令版本、回执类型、回报人、时间、位置或区域、来源和幂等请求编号。撤回确认使用回执类型“已收到撤回、已停止执行、正在回撤、无法立即停止、人员状态异常、通信中断待确认”。

### 6.3 权限

| 操作 | 司令 | 普通人员 | 执行人员 | 公共屏 |
|---|---:|---:|---:|---:|
| 创建和保存草稿 | 是 | 按权限 | 否或按授权 | 否 |
| 提交待核验 | 是 | 是 | 可提交回报 | 否 |
| 核验 | 是或授权 | 否 | 否 | 否 |
| 发布 | 是或既有授权 | 否 | 否 | 否 |
| 撤回 | 是或既有授权 | 否 | 否 | 否 |
| 命令接收 | 可查看 | 否 | 是 | 否 |
| 执行回执和异常 | 可查看 | 否 | 是 | 否 |
| 公共态势查看 | 可查看 | 可查看 | 可查看 | 是 |

公共屏只显示当前有效且已发布的公开字段。

## 7. P1 专项规则

### 7.1 撤离路线

撤离路线必须有起点、终点、适用对象、责任单位、路线状态、来源和核查时间。首版终点只能引用已登记且有效的集结点、医疗救护点、重点保护目标，或具备司令确认记录的“安全终点”记录；“避难场所”和“安全区域”不是首版独立对象类型，必须通过 `endpoint_basis`、坐标、来源、责任单位和安全确认时间形成安全终点记录。

路线状态：

```text
建议路线 → 待核查 → 已确认 → 通行受限 → 已封闭 → 已完成撤离
```

规则：

- 穿过已发布危险区为三级阻断，不得发布；
- 进入待核验危险区为二级复核，不得确认；
- 经过已确认完全阻断点为三级阻断；
- 经过通信盲区为二级复核，不能自动判定失联；
- 主备路线均受阻时升级四级待决断；
- 主路线和备用路线可以同时存在，但同一适用人群不能同时拥有两条当前确认主路线；
- 无人数来源显示“人数待核实”；
- 无完成回执不能标记“已完成撤离”；
- 路线封闭后重新开放必须重新核查并建立新版本；
- 首版不自动生成替代路线、不自动改道、不自动判断道路承载能力。

### 7.2 其他 P1 统一限制

- 危险区、过火区和火场范围必须独立建模，不能互相冒充；
- 通信盲区不能由回报超时自动生成，也不能自动等同于失联；
- 风向不能自动生成或改写蔓延方向；
- 道路阻断点不能自动代表道路全线阻断；
- 集结点必须有安全状态，进入已发布危险区时不能发布；
- 预备队待命点不能显示为实时队伍位置；
- 起降点不能由无人机位置自动生成；
- 影像覆盖只能生成候选或待核验对象；
- 过期对象进入“需要复核”，不自动删除，也不能无条件作为正式依据；
- 跨事件关联、未知来源发布、非法几何保存、空关键字段发布全部拒绝。

### 7.3 P1 发布矩阵

| 类型 | 几何 | 提交核验必填 | 发布前置 |
|---|---|---|---|
| 撤离路线 | 线 | 起点、终点、适用对象、责任单位、来源、核查时间 | 终点有效、无三级阻断、有关联命令或司令确认 |
| 通信盲区 | 面 | 发现方式、发现时间、影响对象、来源 | 有通信测试、现场报告或设备记录 |
| 封控线 | 线 | 原因、责任单位、启用时间、解除条件 | 有命令或司令确认 |
| 道路阻断点 | 点 | 道路名称、阻断程度、发现时间、来源 | 完全阻断须有现场或有效外部依据 |
| 集结点 | 点 | 用途、责任单位、启用状态、安全状态 | 不在已发布危险区，有安全确认时间 |
| 预备队待命点 | 点 | 队伍编号、负责人、待命状态、回报时间 | 队伍有效且有待命回报 |
| 过火区 | 面 | 过火时间、判定依据、复查状态、责任单位 | 有现场报告、影像或复查记录 |
| 风向风速 | 点或方向线 | 风向、测量时间、位置、来源 | 风向来源有效，风速有实测来源才显示数字 |
| 观察哨 | 点 | 责任人或单位、启用状态、最后回报时间 | 有人员安排或现场登记 |
| 无人机起降点 | 点 | 点位类型、责任单位、保障状态、安全检查状态 | 有场地登记且安全检查通过 |

所有 P1 类型的发布还必须满足事件归属、合法几何、有效时间、责任主体、关联对象和核验记录要求。缺少条件时只能保存草稿或待核验，不得发布。

### 7.4 P1 时间有效性

复核周期固定为：危险区、撤离路线、风向风速 30 分钟；道路阻断点、观察哨 60 分钟；通信盲区、封控线、集结点、无人机起降点 120 分钟；预备队待命点在每次队伍状态变化时复核；过火区在每个处置阶段复核。周期用于提醒，超过周期标记“需要复核”，不自动删除，不自动变为安全或危险。

## 8. 路线冲突和四级决断

### 8.1 冲突等级

| 等级 | 含义 | 处理 |
|---|---|---|
| 一级提示 | 靠近通信盲区、过火区或观察哨等，不直接阻断 | 可保存、可提交，发布前须查看 |
| 二级复核 | 进入待核验危险区、通信盲区或待核验阻断影响范围 | 可保存草稿，不得发布 |
| 三级阻断 | 穿过已发布危险区、完全阻断点、失效终点或无有效命令 | 不得发布，不得用“已查看”解除 |
| 四级决断 | 主备路线均受阻、关键保障不足、命令与风险矛盾 | 形成司令待决断事项 |

冲突计算以路线版本和触发对象版本为输入。同一路线命中多个冲突时，最终等级按四级决断、三级阻断、二级复核、一级提示从高到低取最高级，所有命中关系保留在冲突明细中。单条路线的三级阻断只有在它是任务唯一可用路径，或与其他路线、保障事实共同造成行动不足时，才升级为任务级四级决断。

首版默认空间阈值：距危险区边界 0 至 50 米至少二级复核，50 至 150 米一级提示；使用米制地表距离计算，坐标顺序为 `[纬度, 经度]`。阈值是地图提示范围，不是现场安全结论。

### 8.2 四级事项

四级事项必须独立记录编号、触发对象、受影响路线或任务、事实来源、当前风险、可选处置、有效时段、司令决断和关联命令。页面固定分开显示：

```text
已知事实
系统判断
处置建议
司令决断
```

司令可选择：

```text
重新组织
暂停执行
确认例外继续
请求补充信息
```

其中例外继续必须填写理由、适用对象、风险范围、补充保障、开始时间和截止时间。例外不会删除原冲突，不能自动清除阻断。

### 8.3 冲突处置流程

```text
发现冲突
→ 记录事实和来源
→ 生成一级至四级事项
→ 责任单位补充或复核
→ 必要时进入司令待决断
→ 司令明确处置
→ 形成或修订命令
→ 权限和政策校验
→ 执行单位接收
→ 回执和异常处置
→ 独立核验
→ 冲突关闭或重新升级
```

冲突只能通过路线修改、风险对象重新核验、阻断解除、集结点恢复、有效决断或任务取消等明确业务结果消除。关闭图层、点击已查看、刷新页面、改名称或写备注都不能消除冲突。

## 9. 命令、接收、回执和异常

### 9.1 命令确认与接收

命令确认和执行单位接收是两个独立动作。执行单位接收前必须看到目标、单位、路线、起终点、开始时间、完成时限、安全条件、停止条件、回执要求和当前冲突等级。

接收结果：

```text
已接收，具备执行条件
已接收，部分条件待补充
暂不能接收
无法执行，请求重新组织
```

命令未接收不能进入执行中。

### 9.2 接收超时

演示默认：

| 任务等级 | 首次提醒 | 责任单位升级 | 重新组织判断 |
|---|---:|---:|---:|
| 紧急 | 2 分钟 | 5 分钟 | 8 分钟 |
| 高风险 | 5 分钟 | 10 分钟 | 15 分钟 |
| 普通 | 10 分钟 | 20 分钟 | 30 分钟 |

超时只产生提醒、升级和待处理事项，不自动判定拒收、失败、失联，不自动改派单位或改线。

### 9.3 重新发送、暂停、撤回和重新组织

**重新发送**只适用于内容、路线、执行单位、任务等级和依据版本均未变的原命令。内容有变化必须建立修订版，重发不重置超时历史、不延长有效期。

**暂停**必须填写原因、暂停时间、重新评估时间、人员安全要求和等待信息。暂停后不能提交普通执行中回执。

**撤回**分为撤回申请、通知已发送、执行单位待确认、已确认停止、撤回完成。执行中撤回必须有停止、回撤或无法立即停止的回执。无法立即停止至少建立二级执行异常，涉及人员安全时升级。

撤回确认使用命令控制状态和回执记录共同表达：命令控制状态依次为“撤回通知已发送、等待停止确认、撤回执行中、撤回完成”；对应回执类型为“已收到撤回、已停止执行、正在回撤、无法立即停止、人员状态异常、通信中断待确认”。在“撤回完成”前，内部地图保留原路线并显示撤回处理中，公共屏不显示内部过程。

**重新组织**先冻结原命令，再区分已完成、执行中、未开始、无法执行和待转交内容，然后由司令明确选择等待原单位、更换执行单位、拆分任务、调整范围、延期或取消。涉及单位、目标、路线、时间和安全条件的变化都必须产生新命令版本，新单位必须重新接收。

### 9.4 执行回执

回执类型：

```text
已到达、执行中、阶段完成、全部完成、部分完成、无法执行、执行异常、人员安全异常、通信异常、任务暂停
```

回执必须包含命令编号和版本、回报人、时间、位置或区域、已完成和未完成内容、人员状态、现场风险、下一步需求及来源。回执不自动覆盖正式队伍位置，不自动把计划路线变成实际轨迹，不自动生成正式火线。

紧急任务默认回执要求：接收 2 分钟，开始执行确认 3 分钟，首次现场回执 5 分钟，执行中每 5 分钟一次，进入高风险区域每 2 分钟一次，异常后 3 分钟内补充，完成回执 5 分钟内提交，完成后 15 分钟内进入独立核验。超时只提醒，不自动判定失联。

### 9.5 执行异常和关闭

异常等级：

```text
一级记录提醒
二级任务复核
三级执行阻断
四级紧急决断
```

异常必须有类型、时间、位置、影响、来源、当前措施和支援需求。人员安全异常优先于任务完成状态。异常升级必须记录前后等级和原因，降级必须有新事实或明确确认。

异常关闭前必须完成：

```text
事实闭合 + 处置闭合 + 结果闭合
```

关闭结果只能为已处理、已转交、已暂停、已撤回、误报确认、无法核实关闭或异常结束。异常已处理不等于命令完成，无法核实不等于成功。

命令关闭前必须有完成或部分完成回执、人员状态确认、异常处理结果、路线状态一致性、独立核验或明确的无法核验结论。命令结果区分已完成、部分完成、未完成关闭、已取消、异常关闭和无法核验。

| 风险环境 | 07 | 危险区、通信盲区、道路阻断点、过火区、风向风速、观察哨 | 关 |
| 证据影像 | 02 | 无人机位置、影像覆盖区、无人机起降点 | 关 |

08 至 12 是跨业务图层的状态或交互渲染层，不计入六组业务图层：08 为草稿与待核验，09 为执行观察和回执，10 为方案推演，11 为历史撤回，12 为当前选中高亮。业务图层关闭时，所属对象的图形、标签和点击热区同步隐藏；状态层不能绕过业务图层、权限或公共屏过滤。

默认开启火情、防控、兵力、指挥保障。危险区属于火情核心对象但位于风险环境图层，默认关闭。重点保护目标固定归入指挥保障组并默认开启。影像、风险环境、通信、撤离、集结点、历史和方案推演按对象级开关或子图层开关控制，不能由“按需”自由解释。

计数口径固定：23 个演示实例指 22 个地图对象加 1 个 W-03 缺口子记录；地图对象数量只按对象编号计一次，状态层、执行观察层和方案推演层不重复计数。首屏对象数量指默认图层、默认缩放级别下实际可见的地图对象；隐藏图层中的对象不计入首屏可见数量，但计入事件对象总数。

### 10.2 显示规则

| 状态或对象 | 显示 |
|---|---|
| 已发布 | 实线、实心、正常透明度 |
| 已核验未发布 | 实线、较高透明度，标“已核验·待发布” |
| 待核验 | 橙色虚线、半透明 |
| 草稿 | 灰色虚线、低透明度 |
| 计划 | 点划线或斜纹 |
| 方案推演 | 独立虚线和斜纹，标“推演·非正式态势” |
| 已撤回或失效 | 灰色低透明度，默认历史层 |
| 异常或阻断 | 保留原类别颜色，叠加红色边框、纹理和中文状态 |

隔火带保存中心线和米制宽度，地图显示带状区域。典型桌面缩放下显示宽度 8 至 14 像素，不能用像素冒充现场宽度。计划带、已开设带和缺口必须有不同的线型、填充或状态标识。

无人机位置和影像覆盖区分离。普通图片允许人工平移、缩放、旋转和调整透明度，始终标记“人工粗略覆盖，不作为精确坐标依据”。影像覆盖位于正式态势下方，不能遮住火线、队伍路线和保障点。

### 10.3 联动处理顺序

```text
权限过滤
→ 事件过滤
→ 对象版本过滤
→ 撤回和失效过滤
→ 状态过滤
→ 业务图层过滤
→ 空间关系检查
→ 路线冲突计算
→ 待复核和待决断更新
→ 紧急异常高亮
→ 标签避让
→ 当前选中高亮
```

对象变化先写入新版本和审计，再计算空间关系和冲突，最后刷新图形。冲突计算失败不得显示“无冲突”，必须保留上一结果并标记待更新，禁止基于旧数据确认高风险命令。

### 10.4 联动允许和禁止

允许自动产生：

```text
提示、需要复核、发布阻断、待补充信息、待司令决断、关联对象定位和待办
```

禁止自动产生：

```text
发布、撤回、改线、移动队伍、修改火线、扩大危险区、判定失联、生成正式命令、关闭异常或关闭任务
```

命令、回执和地图状态只做状态关联：命令草稿显示计划路线，已确认命令显示待接收或确认路线，执行中显示执行状态，异常显示警示，完成后进入历史。回执不直接改写正式事实。

### 10.5 公共屏

公共屏只读取当前事件中已发布、未撤回、当前有效版本的公开字段。公开字段白名单固定为：对象名称、对象类型、公开状态、位置或范围、责任单位、最后更新时间、必要的路线起终点和必要的安全提示。来源编号、原始备注、内部冲突等级、四级事项、例外理由、命令接收状态、执行异常详情、未配准影像信息和内部审计字段不得公开。以下内容显示数量必须为 0：草稿、待核验、方案推演、命令接收超时、内部执行异常、四级待决断、例外理由、内部冲突等级和未配准影像细节。

## 11. 页面交互定稿

### 11.1 桌面端

地图占首屏可用区域不低于 65%。顶部状态条 48 至 56 像素，左工具栏 48 至 64 像素，右侧工作区 320 至 420 像素。右侧信息窗按对象类型显示专属字段，不能所有对象共用“名称加备注”。

工具栏收敛为：

```text
火情｜作业｜兵力｜保障｜环境与证据
```

同一时间只激活一个绘制工具。绘制完成后先预览，再保存草稿或提交核验。取消绘制不生成对象、不写业务审计事件。

### 11.2 核心操作步数

```text
火场范围：选工具 → 连续点选 → 完成 → 填依据来源时间 → 保存草稿
隔火带：选工具 → 画中心线 → 完成 → 填宽度和责任小队 → 带状预览和保存
小队路线：选工具 → 选小队和路线类型 → 连续点选 → 完成 → 填任务命令 → 保存
点对象：选工具 → 地图落点 → 填专属字段 → 保存草稿
```

### 11.3 移动端

地图占主屏，工具栏变为底部工具组，信息窗变为底部抽屉，支持：

```text
关闭 → 预览态 → 半屏态 → 全屏态
```

绘制支持触摸，不依赖悬停。完成、撤销、取消、保存按钮必须直接可触摸，页面不得横向滚动，文字不得溢出。

### 14.2 方案叠加的取消与互斥（2026-08-28 补，不改本定稿口径）

背景：三套预案常驻右下方案区，“可分别上图”不等于“可无限叠加而不撤”。
旧实现下每套方案各自开关，且每套都重画一份预测火线，切方案时前一套不消，
图上就只剩重复虚线。本节把“怎么上图、怎么取消、怎么还原”定成硬口径：

```text
1) 默认互斥：任一时刻只有一套方案的推演对象在图上；点另一套「上图」即自动下掉前一套。
2) 推演公共层（预测火线、目标圈、最大漫衍半径）属于态势而不属于方案，
   全图只画一份；切方案时它们不变，变的只有该方案自身的作业对象。
3) 对比是显式动作：只在地图叠加条上开了「多方案对比」才允许多套同屏，
   并自动降低透明度；关掉对比回到互斥（保留最后上图的一套）。
4) 叠加状态必须在图上可见：已上图的方案色点 + 名称常驻叠加条，
   方案卡同步描边高亮；不允许“图上有东西而不知道是什么”。
5) 「全部下图」＝恢复原始态势视图：推演层、目标圈、证据影像覆盖、
   候选/草稿显示全部关掉；只拨显示开关，不删一条标绘数据；
   叠加条保留并给「恢复上图前显示」还回原开关。
6) 上图是只读查看动作：指挥员与现场人员均可用；公共屏无叠加入口、无方案载荷。
7) 叠加偏好按事件分键持久（刷新不丢），但绝不写回正式态势与审计链。
验证：全量回归 736 OK；浏览器实测切方案时火线层 6→6（旧为 6→12）、
      全部下图后矢量对象 27→21、还原后 21→27、刷新后仍保留所选方案。
```
