# 17 · 前指平台对接契约（草案 V0.9）

> **状态**：草案——供平台工程师团队评审，评审通过后升 V1.0 冻结。
> **目的**：把熊猫智脑（决策大脑）嵌入森林草原火灾前指应急指挥作战平台（三端外壳）时，
> 两系统的边界、数据格式与责任划分固化为可实现的接口契约。
> **上游依据**：《森林草原火灾前指决策辅助平台建设方案》（0708 报送稿）、
> ICS 二期 PRD-001~010、《陕西省前线指挥部工作指南》、《灭火组织指挥手册》。

---

## 一、总则：订单所有权七条规则

| # | 规则 | 理由 |
|---|---|---|
| 1 | **订单状态机唯一属主是智脑**。平台界面显示的"已送达/已接收"只是投影；智脑的订单结局只认回流到事实账的证据 | 单一事实源，防两套状态打架 |
| 2 | **修改=新版本，绝不覆盖**。改单必须回到智脑走变更（乐观锁+新审计事件），出新版工单 | 一线永远收不到被悄悄改过的任务 |
| 3 | **撤销/暂停只能从权力链发起**。总指挥在工作台操作 → 智脑记账 → 平台收到撤回工单；反向不成立 | 保审计链连续 |
| 4 | **分类准入**：涉火场处置、动用兵力、带安全风险的**作战任务**必须过智脑决断门；纯行政保障事务（食宿调度等）平台自治 | 决断门不被垃圾任务淹没 |
| 5 | **交接双记账**：每次出界写一对互引事件（智脑记 `OrderDispatched(dispatch_id)`，平台记 `dispatch.order_id`） | 责任链跨系统无缝回放 |
| 6 | **幂等重发**：工单以 `order_id` 为幂等键，重复投递一线不重复执行 | 弱网必配 |
| 7 | **全程本地**：两系统同跑前指局域网（智脑零外依）；三断场景照常运转 | 兑现 Mesh 离线承诺 |

自动化阶梯：**L1 起草自动化+人在环决断（v1）→ L2 白名单内授权自动执行（远期渐进）→ L3 数字人语音交互（界面层，外部条件就绪后）**。v1 的"一句话指挥"= 一句话起草 → 将军确认 → 受控执行。

## 二、任务工单（智脑 → 平台）

智脑侧命令经决断门激活（`ExecutionOrder.status=active`）后，产出工单载荷移交平台派发系统：

```json
{
  "work_order_id": "wo-<order_id>",          // 幂等键，= order_id 一一对应
  "order_id": "order-123",                   // 智脑权威引用
  "decision_id": "dec-456",                  // 可回溯到决心
  "brief_id": "brief-789",                   // 可回溯到简报
  "version": 2,                              // 改单递增，旧版作废
  "title": "东线火头攻坚",
  "engagement": "direct-attack",             // direct-attack | burn-out | fireline-cut |
                                             // mop-up | air-operation | logistics
  "assignee": {
    "pos_code": "pjjz-1",                    // 岗位槽位编码（org_model.POSITION_SLOTS）
    "leader_phone": "139****2876"            // 第一受派人；全号仅指挥模式可见
  },
  "time_window": "day",                      // day | dawn | dusk | night
  "deadline": "2026-08-22T18:00:00+08:00",
  "safety_notes": ["夜间禁止直抗", "预设安全区"],   // 政策检查附注
  "material_list": [                          // 算模块物资需求（可选）
    {"item": "高压水泵", "unit": "台", "qty": 6}
  ],
  "audit_hash": "<sha256>"                   // 激活事件的审计哈希，供双记账互验
}
```

## 三、执行状态事件（平台 → 智脑）

平台的送达/接收/执行回执作为**观测事件**回流智脑事实账，走既有摄取纪律
（参照 docs/15：摄取≠验证，平台上报状态属 AUTHORIZED 源的人工报告类证据）：

```json
{
  "event_type": "task_status",               // dispatched | received | in_progress |
                                             // completed | exception | recalled
  "work_order_id": "wo-order-123",
  "dispatch_id": "disp-001",                 // 平台账本主键（规则⑤互引）
  "pos_code": "pjjz-1",
  "reporter": "张三",                        // 上报人（队长）
  "occurred_at": "2026-08-22T15:04:00+08:00",
  "detail": "一分区火线扑打完成，转入清理"
}
```

处理规则：
- 状态事件进事实账后，是否终结订单由智脑核验流程裁决（`VerificationFinished` 等），
  平台状态**永不直接改写** `ExecutionOrder.status`；
- `exception` 类事件按既有请示流转为 GeneralQuestion，交将军决断；
- 断网续传批次合并后补传，按 `(work_order_id, event_type, occurred_at)` 幂等去重。

## 四、花名册同步（平台 → 智脑）

扫码入岗（PRD-001）产生的绑定实时同步智脑编成模型。字段与 PRD-001 同构，
手机号为常备人员库与花名册的唯一关联键：

```json
{
  "sync_type": "checked_in",                 // checked_in | checked_out
  "task_ref": "<平台 task_id>",
  "person": {
    "name": "张三",
    "phone": "13900000001",                  // 唯一键
    "unit": "鄠邑区消防救援大队",
    "home_position": "扑救员",
    "is_leader": true
  },
  "pos_code": "pjjz-1",                      // org_model 内置模板槽位编码
  "occurred_at": "2026-08-22T14:30:00+08:00"
}
```

- 智脑侧落账事件：`PersonCheckedIn` / `PersonCheckedOut`（含审计哈希）；
- 同步失败重试同样幂等（键 = phone + pos_code + sync_type + occurred_at）；
- 编成视图渲染规则：观察态电话脱敏（`mask_phone`），指挥态全号可外呼——
  与 PRD-010 数据脱敏要求一致。

## 五、分类准入判定

| 判据（满足任一即为作战任务，走智脑） | 例 |
|---|---|
| 在火线上部署/调动人员 | 扑打、清守、点烧、突破 |
| 触发安全规程约束的动作 | 夜间作业、点烧、空中作业 |
| 动用武装力量或高危装备 | 直升机、灭火炮 |
| 影响保护目标安全的处置 | 转移群众、重点目标防守 |

行政保障类（食宿、车辆、物资出入库日常流转）平台自治，无需过决断门。
判定存疑时默认走智脑——多一道审计不算错。

## 六、离线降级行为

1. 正常态：平台前端 ↔ 前指服务 ↔ 智脑内核同机/同网运行；
2. 公网断：一切照常（两系统本就不依赖公网）；
3. 局域网受损（Mesh 部分节点失联）：平台负责队列缓存与续传（PRD-005），
   智脑侧事件到达顺序不代表发生顺序，以 `occurred_at` 为准重建时序；
4. 智脑进程重启：工作区从快照恢复（SQLite 快照机制），未落盘事件由平台侧重传补齐。

## 七、集成阶段划分

| 阶段 | 内容 | 前置条件 |
|---|---|---|
| v1（当前） | 智脑自带工作台，CSV 导入花名册+模拟扫码桥接，数据流与真集成完全一致 | 无 |
| v1.5 | 平台实现花名册同步 webhook → 替换模拟事件源；工单出界对接平台派发 API | 本契约评审通过 |
| v2 | 执行状态全量回流+复盘合流；算模块接入平台资源池真实库存 | v1.5 稳定运行 |

## 八、待工程师团队评审确认的问题

1. 工单推送通道选型：REST 回调 or WebSocket 订阅（建议后者，与 PRD-010 开放接口一致）；
2. 平台 `task_position` 的 pos_code 是否直接采用本契约槽位编码表（建议采用，避免映射层）；
3. 电话号码全号字段的鉴权粒度（建议沿用智脑指挥模式口令体系）；
4. 北斗短报文通道（PRD-008）是否也回流智脑事实账（建议是，报文模板加 event_type 映射）。
