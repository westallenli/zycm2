## 1. 设计结论

沙盘不能把“数据更新”直接等同于“正式态势变化”。

本专项采用下列模式：

> **自动发现 + 参谋层更新 + 指挥员手动复核当前态势。**

```text
已校验数据进入事件空间
  → 自动发现变化、时效、矛盾或空间冲突
  → 更新观察层、候选层、风险/推演层和待处理变化台账
  → 提示指挥员“有变化待复核”
  → 指挥员点击「复核当前态势」
  → 固定本轮数据截止点，形成可追溯的态势复核结果
  → 生成修订建议、信息补充申请、方案影响或重新决断建议
  → 核验 / 指挥员确认后，才形成正式态势新版本或新命令
```

本专项的核心不是做一个“刷新按钮”，也不是让地图跟随模型自动漂移，而是让系统持续发现现实变化，并把它们有边界地送入参谋判断和人工复核流程。

## 2. 目标、范围与非目标

### 2.1 目标

1. 新数据进入后，系统能自动识别值得关注的态势变化；
2. 自动发现结果可形成待核验候选、时效提示、冲突记录、方案影响或信息缺口；
3. 指挥员能主动点击「复核当前态势」，获得以明确数据截止点为依据的一轮态势复核；
4. 每次自动发现与手动复核均可追溯来源、时间、影响对象、版本和处理结果；
5. 正式态势、正式命令和执行状态保持稳定，不被自动发现或参谋判断静默改写。

### 2.2 本批范围

- 事件空间内的态势变化台账；
- 已校验数据进入后的自动发现编排；
- 对现有时效、冲突、候选、推演和方案影响能力的统一接线；
- 指挥员「复核当前态势」业务动作；
- 沙盘右侧的待复核变化、上次复核和复核结论展示；
- 沙盘只读更新载荷与轻量前端刷新；
- 变化、复核和处理结果的哈希链审计与 SQLite 快照持久化；
- 演示数据下的确定性验证场景。

### 2.3 本批不做

以下内容明确不属于本批：

- 接入真实北斗、传感器、无人机视频流或气象实时服务；
- 宣称当前已经有真实实时数据；
- 自动识别真实火线、自动规划路线、自动生成精确隔火带；
- 用大模型自动发布正式态势、撤销命令、改写执行状态或调派队伍；
- 把每一条数据都送入完整参谋部或大模型调用；
- 全量重构现有 `ScenarioWorkspace`、模型系统或外部平台接入体系；
- 将公共屏改成候选、方案或待决断事项展示屏。

## 3. 不可突破的边界

### 3.1 权力与写入红线

持续遵守：

```text
AdvisorProposal → GeneralDecision → ExecutionOrder → Policy/Approval → Executor
```

- `workspace.append_event` 仍为哈希链唯一写入口；
- 自动发现属于低风险观察与参谋工作，不是指挥员决断；
- 自动发现不能直接修改已发布对象的几何、标题、责任单位、路线、有效状态或发布状态；
- 自动发现不能直接暂停、撤销、下达、重发或完成命令；
- 自动发现不能把执行回执改写为独立核验结论；
- 已发布对象若需改变，必须生成新修订草稿，保留原对象和版本关系；
- 发布、撤回、核验和命令动作继续要求指挥员授权。

### 3.2 三层地图口径

地图展示固定分为三层，不得混淆：

| 层级 | 含义 | 是否自动更新 | 是否可静默改变正式态势 |
|---|---|---:|---:|
| 正式态势层 | 当前组织认可、可作为指挥依据的对象 | 仅更新时效提示 | 否 |
| 参谋变化层 | 新观测、候选、待核验修订、矛盾和异常提示 | 可以 | 否 |
| 推演层 | 预测火线、风险热区、预计影响范围、方案推演 | 可以重新计算 | 否 |

正式态势可以自动被标记为“需要复核”或“已超过复核周期”，但仍然保留为当前正式版本；这不是更新其业务事实，更不是替换其边界或路线。

### 3.3 坐标与影像边界

- `geo_points` 是真实地图对象的权威位置；旧示意 `points` 不可作为自动分析、冲突判断或真实地图候选的替代坐标；
- 高德底图与 WGS84 标绘可能存在数十至数百米偏移；任何自动空间比对、路线冲突和候选定位都必须显示坐标系/定位质量限制；
- 人工粗略覆盖、未配准影像和示意坐标只能形成证据或待核验提示，不能作为精确火线、危险区、人员位置或命令路线的正式依据；
- 坐标未知、定位精度不足或来源未授权时，系统应提出信息缺口，不得编造空间结论。

## 4. 现有基础与改造缺口

### 4.1 可直接复用的现有能力

| 能力 | 当前位置 | 本专项用途 |
|---|---|---|
| 标绘状态机、候选来源、修订草稿 | `impl/panda_brain/map_annotations.py` | 自动发现结果只能进入草稿/待核验；已发布对象通过修订草稿变更 |
| 逐类核验与发布闸门、时效计算、空间冲突 | `impl/panda_brain/tactical_map.py` | 自动发现的确定性规则基础 |
| 标绘、冲突台账、方案受影响、审计链 | `impl/panda_brain/workspace.py` | 所有业务结果的统一持久化与审计 |
| 地图分层、候选/草稿/推演显示、方案叠加 | `impl/panda_brain/sandview.py` | 地图展示、变化提示、轻量更新载荷 |
| 沙盘动作、事件空间快照、影像/导入入口 | `impl/panda_brain/panel.py` | 统一数据进入后触发、复核动作和 HTTP 接线 |
| 规则推演 | `impl/panda_brain/sand_sim.py` | 基于最新已认可输入重算预测层，仍不写回正式态势 |
| 观测数据校验与幂等原型 | `impl/panda_brain/ingestion.py` | 后续统一数据接入的校验原则参考，不直接等同于消防实时接口 |

### 4.2 当前缺口

1. 页面地图载荷只在首屏生成；前端 `refresh()` 仅刷新本页图层显示，不会读取新的态势数据；
2. 时效与冲突已有规则，但没有一个“数据进入后统一发现与编排”的入口；
3. `advisor_log` 仅为内存通知，重启后消失，不能承担业务态势变化记录；
4. 现有“生成预案/重新参谋”是泛化全轮编排，没有明确数据截止点、变化集、去重和前后差异，不应直接替代“复核当前态势”；
5. 影像分析与部分候选仍属演示路径，不能包装为已接入实时智能识别；
6. 候选与旧正式对象之间缺少稳定的“质疑/建议修订/替代关系”；
7. 缺少自动发现结果的幂等键、处理状态、抑制策略和可审计摘要。

## 5. 领域对象设计

### 5.1 态势变化记录 `SituationChange`

新增独立领域对象，不能复用内存 `advisor_log`，也不能把变化说明塞进标绘备注。

建议字段：

```text
change_id                 变化编号
incident_id               事件编号
kind                      变化类型
status                    new / acknowledged / reviewed / superseded / dismissed
severity                  notice / review / decision
source_refs               来源编号列表
source_digest             本次来源摘要哈希
observed_at               原始数据观测时间
received_at               系统接收时间
detected_at               规则发现时间
affected_annotation_ids   受影响标绘
affected_option_ids       受影响方案
related_change_id         可选：替代或合并的变化
candidate_annotation_ids  产生的候选标绘
reason                    面向业务的变化说明
evidence_summary          可阅读的依据摘要
positioning_notice        坐标/配准限制
rule_version              发现规则版本
fingerprint               幂等指纹
review_batch_id           被哪次复核处理
resolved_at               处理时间
resolution                核验、忽略、形成修订、转决断等业务结果
```

初版变化类型固定为：

```text
source_freshness_expired        正式对象超出复核周期
source_conflict_detected        路线与风险/阻断/通信盲区冲突
source_observation_conflict     新观测与正式对象不一致
source_candidate_created        新数据形成待核验候选
source_information_gap          关键来源缺失、过期或定位不足
source_option_affected          新变化影响在议/已采纳方案
```

不得先扩展为无限制文本类型。每一类型都必须能指出来源、影响对象和允许的后续动作。

### 5.2 态势复核批次 `SituationReviewBatch`

指挥员点击「复核当前态势」后创建一条复核批次，固定本次判断所依据的数据边界。

建议字段：

```text
review_batch_id
incident_id
requested_by               指挥员
requested_at
cutoff_at                  本轮数据截止时间
workspace_version_before
source_change_ids          本轮纳入的待处理变化
source_refs                本轮纳入的来源
prior_review_batch_id      上一轮复核
summary                    本轮摘要
new_findings               新发现
invalidated_findings       已失效或需要复核的旧判断
information_gap_ids        新增/仍未关闭的信息缺口
candidate_annotation_ids   新增候选或修订草稿
affected_option_ids        受影响方案
recommendation             是否建议重新决断/补充信息/维持现状
requires_commander_action  是否需要指挥员处理
outcome                    completed / no_material_change / blocked
fingerprint                同一截止点的幂等指纹
```

`SituationReviewBatch` 是参谋业务结果，不是正式态势发布记录，也不是命令。

### 5.3 标绘关联扩展

为待核验候选和修订草稿补充可选关联，建议复用 `MapAnnotation.details` 之外的受控字段：

```text
challenged_annotation_id   该候选质疑的正式对象
change_id                  产生该候选的态势变化记录
review_batch_id            产生或纳入该候选的复核批次
```

约束：

- 自动候选的 `source=ai-suggestion`，状态只能是草稿或待核验；
- 若挑战已发布对象，必须保留 `challenged_annotation_id`；
- 指挥员确认要改变正式对象时，必须走原有修订草稿、核验和发布链；
- 自动候选不得替代原对象，更不得自动撤回原对象。

## 6. 自动发现规则与触发策略

### 6.1 自动发现的定位

自动发现只执行可解释、低风险、可重复的规则扫描。它不负责最终认定，不以“模型认为”替代事实。

```text
已校验来源数据
  → 数据有效性、来源和定位质量检查
  → 确定性变化扫描
  → 新建或合并态势变化记录
  → 必要时创建待核验候选/信息缺口/冲突记录
  → 标记受影响方案
  → 提醒指挥员复核
```

### 6.2 初版触发源

第一批仅接入现有且可审计的入口：

1. 已登记的无人机影像状态变化或分析结果；
2. 已确认的外部报警更新；
3. 已授权的数据导入发布；
4. 已接收的执行回执、人员状态和位置类更新；
5. 指挥员或授权人员提交并通过校验的标绘/修订；
6. 定时的时效扫描。

未来真实传感器、北斗、气象、通信、外部平台和视觉模型只要通过数据接入契约校验，即可复用同一“数据进入 → 自动发现”入口；本批不伪造这些来源。

### 6.3 初版自动规则

| 规则 | 输入 | 自动结果 | 禁止结果 |
|---|---|---|---|
| 时效超期 | 已发布或已核验对象的复核时间 | 新建/更新“需要复核”变化记录 | 不撤回、不删对象、不改变几何 |
| 路线冲突 | 路线、危险区、阻断点、通信盲区 | 新建冲突记录、变化记录、影响方案 | 不自动改道、不暂停命令 |
| 新观测矛盾 | 新来源与正式对象的位置/状态/时间明显不一致 | 候选或修订建议、待核验变化 | 不覆盖正式对象 |
| 关键来源缺失 | 数据超期、来源无效、坐标不确定、关键字段缺失 | 信息缺口和待复核提示 | 不假定安全或完成 |
| 新候选形成 | 有合格来源、定位质量满足候选标准 | 草稿或待核验候选 | 不直接发布 |
| 方案受影响 | 变化关联到方案前置条件、风险区或路线 | 标记方案“受态势影响·需复核” | 不自动否决或采纳方案 |

### 6.4 触发节流与幂等

实时不等于每条数据都发起完整研判。

- 每个变化必须按 `incident_id + change_kind + affected_object + source_digest/rule_version` 生成幂等指纹；
- 相同数据重复到达只能更新引用/最后发现时间，不得重复生成候选、冲突或提示；
- 同一对象同类提示未处理时应合并，不得反复刷屏；
- 只有变化等级升级、来源显著更新、影响对象扩大或距离上次复核超过设定周期时，才升级通知；
- 自动发现不调用完整参谋编排；完整复核只由指挥员点击或未来明确授权的高优先级机制发起。

初版可采用事件到达触发 + 页面打开时只读检查；不得依赖浏览器开着才完成后台业务检查。后续若增加后台调度器，调度器仅执行规则扫描与通知汇总，不获得发布或命令权限。

## 7. 手动「复核当前态势」动作

### 7.1 权限

- 仅指挥员可发起；
- 现场人员可查看变化、候选和已完成复核摘要，但不能发起复核、发布标绘或处理命令；
- 公共屏仅显示已发布正式态势，不下发变化台账、候选、复核摘要、方案或待决断信息。

### 7.2 业务语义

按钮名称固定为：

```text
复核当前态势
```

不使用“智能参谋”“刷新 AI”“重新计算地图”等技术性或含义不清的名称。

指挥员发起后：

```text
固定数据截至时间
  → 汇总未处理变化与相关来源
  → 重新计算可刷新推演层
  → 检查正式态势的时效、冲突和修订建议
  → 检查在议/已采纳方案是否受影响
  → 输出事实、判断、建议、待处理事项四类结果
  → 写入态势复核批次及审计链
```

### 7.3 输出格式

复核结果必须面向业务，不展示模型、Agent、提示词或推理过程。建议固定呈现：

```text
本次态势复核
数据截至：YYYY-MM-DD HH:MM
较上次复核：新增 X 项 / 失效 X 项 / 维持 X 项

事实变化
- 新增无人机影像覆盖东南坡，定位状态：人工粗略覆盖。

判断变化
- 东南侧正式火线已超过复核周期；新影像与原边界存在差异，需核验。

建议处置
- 核验东南侧火线边界；复核 T-04 路线；补充风向实测来源。

待指挥员处理
- 是否将“东南侧火线修订草稿”提交核验。
- 方案乙受态势影响，建议重新比较。
```

若无实质变化，必须如实输出：

```text
本次复核未发现需要改变正式态势、方案或命令的事项。
```

### 7.4 幂等行为

同一事件、同一数据截止点、同一规则版本再次点击：

- 不重复生成方案、候选和变化记录；
- 返回同一复核批次及其结果；
- 可记录“再次查看”审计，但不制造新的业务结论；
- 新数据进入后才允许创建新的复核批次。

## 8. 前台设计

### 8.1 指挥助手区

在现有右侧“指挥助手”中增加以下业务区块：

```text
态势复核
数据截至：13:58
上次复核：13:42
待复核变化：3 项（其中需要指挥员处理 1 项）
[复核当前态势]
```

变化卡仅展示业务结果，建议类型：

- 【需要复核】东南侧重点火线超过复核周期；
- 【待核验变化】新影像与正式火场边界存在差异；
- 【路线风险】二分队计划路线进入待核验危险区；
- 【方案影响】方案乙的安全余量下降，建议重新比较；
- 【信息缺口】缺少最新风向实测来源。

每张卡提供有限、明确的业务动作：

- 在地图定位；
- 查看依据；
- 查看候选；
- 提交核验；
- 复核当前态势；
- 按现有资料继续。

不得提供“自动采纳”“自动发布”“立即改图”“自动改令”等动作。

### 8.2 地图视觉规范

- 正式态势保持既有稳定样式；
- 被新数据质疑的正式对象保留原形状，可附“需要复核”角标或时效芯片；
- 自动候选/修订建议使用现有待核验视觉语言（虚线、半透明、明确标签），不得伪装成正式实线；
- 推演层继续使用“预测/推演”样式，并显示数据截至时间与口径；
- 点击变化卡只定位/高亮，不自动改变当前方案叠加、候选显示、证据影像开关或地图缩放；
- 若前端自动收到新载荷，只更新数据层，必须保持用户当前视角、图层开关、方案上图状态和抽屉状态。

### 8.3 页面轻量刷新

新增只读态势更新载荷，供登录后的指挥员/现场人员定时检查：

```text

```

建议载荷仅包含：

```text
workspace_version
feed_version
latest_data_at
latest_review_at
pending_change_count
requires_commander_action_count
new_change_ids
changed_annotation_ids
candidate_annotation_ids
updated_projection
```

前端只在 `feed_version` 变化时再请求完整的只读沙盘数据载荷。不得由定时器发起写入、自动复核或自动决断。

公共屏不提供该接口，也不下发未发布对象和变化信息。

## 10. 实施批次

### P20-1：态势变化内核与审计底座

目标：先建立可持久、可重放、可去重的变化与复核对象，不改前台自动刷新。

- 新增 `SituationChange`、`SituationReviewBatch` 与受控枚举；
- 通过 `workspace.append_event` 写入、回放、持久化；
- 实现时效、冲突、信息缺口、方案受影响四类确定性发现；
- 形成来源、影响对象、规则版本和幂等指纹；
- 自动发现不得修改正式标绘和命令。

完成标准：单元测试证明相同输入不重复写入，重载快照后变化与复核批次一致，哈希链完整。

### P20-2：统一数据进入与候选/修订关联

目标：让现有可信入口能触发自动发现，但不伪造实时数据。

- 在影像、确认报警、授权导入、回执/人员状态、标绘修订等现有入口后接统一编排；
- 将候选与被质疑正式对象、变化记录建立关联；
- 统一更新冲突台账和方案受影响状态；
- 将定位质量不足转化为信息缺口，不生成误导性空间候选。

完成标准：每个入口都能说明来源；重复输入幂等；演示数据明确标识，不对外宣称实时接入。

### P20-3：手动复核当前态势

目标：实现指挥员可控、带数据截止点的复核闭环。

- 新增 `review_current_situation()`；
- 仅指挥员可发起，保留同截止点幂等；
- 输出事实/判断/建议/待处理事项；
- 重新计算推演层，但不自动发布正式对象；
- 在必要时生成修订草稿或待核验候选。

完成标准：能明确展示“本次数据截至”“较上次变化”“无实质变化”三种结果；成员/公共屏权限正确。

### P20-4：沙盘变化卡与轻量刷新

目标：让打开中的沙盘能看到变化，但不打断指挥员当前操作。

- 新增变化卡、复核按钮、上次复核与数据截至信息；
- 新增只读版本检查及按需载荷刷新；
- 保留地图视角、图层开关、方案叠加、本地存储偏好和抽屉状态；
- 公共屏严格隔离；
- 浏览器实测候选、推演、方案叠加和变化卡同时存在时不混乱。

完成标准：新变化出现后指挥员看到业务提示；正式态势不闪烁、不漂移、不被覆盖。

### P20-5：演示闭环与浏览器验收

目标：构造可复现的演示数据链路，验证而非口头声明。

建议演示波次：

```text
T0：已有已发布火线、路线和方案乙
T1：进入新影像/现场报告，生成“火线需复核”与待核验候选
T2：进入危险区变化，生成路线冲突并标记方案乙受影响
T3：指挥员点击“复核当前态势”，生成复核批次和修订建议
T4：指挥员核验、发布修订对象；旧正式对象保留版本关系
T5：再次复核，无实质变化，不重复生成候选和方案
```

## 11. 验收清单

### 11.1 规则和审计

- [ ] 每条自动发现均包含来源、观测时间、发现时间、影响对象、规则版本和幂等指纹；
- [ ] 重复数据不会重复生成变化、候选、冲突和复核批次；
- [ ] 同一数据截止点重复复核返回同一批次，不重复生成方案；
- [ ] 所有变化、复核和处理结果经 `workspace.append_event` 入哈希链；
- [ ] SQLite 快照重载后变化、关联候选、复核结果和链校验一致；
- [ ] `advisor_log` 不作为正式业务记录来源。

### 11.2 正式态势和命令边界

- [ ] 自动发现不能改变已发布火场边界、重点火线、隔火带、路线、队伍正式位置和保护目标；
- [ ] 自动发现只能创建草稿/待核验候选，不能创建已发布对象；
- [ ] 已发布对象发生变化时形成修订草稿，原对象仍保持可追溯；
- [ ] 自动发现不能直接暂停、撤销、下达、重发或完成命令；
- [ ] 执行回执不会被自动当作独立核验结论。

### 11.3 页面与权限

- [ ] 指挥员可看见待复核变化并发起“复核当前态势”；
- [ ] 现场人员可查看变化摘要和候选，不能发起复核、发布态势或改变命令；
- [ ] 公共屏只显示已发布正式态势，不含候选、变化、方案、复核结果或待决断事项；
- [ ] 前台无模型名称、Agent 数量、推理过程、提示词或“正在思考”等技术表达；
- [ ] 前端更新后保持地图视角、图层开关和方案叠加状态；
- [ ] “全部下图（恢复原始态势）”仍只影响显示，不删除变化、候选和正式对象数据。

### 11.4 空间与数据质量

- [ ] 无地理坐标、坐标系未知、定位精度不足或未配准影像不能形成精确空间结论；
- [ ] 高德/GCJ 与 WGS84 偏移限制在相关变化和候选中可见；
- [ ] 人工粗略覆盖影像始终标明不能作为精确坐标依据；
- [ ] 新数据缺少关键字段时生成信息缺口，而不是用默认值补齐；
- [ ] 推演层带数据截至时间、推演口径和“非正式态势”标识。
