# 熊猫智脑 Cola v4 后续开发规划

> 版本：V1.0
>
> 日期：2026-08-25
>
> 适用工作区：`D:/熊猫开发项目/熊猫智脑cola v4`

## 1. 规划结论

产品前台固定为五个业务页面：

1. **火情登记页**：有火情登记权限的人员进入；支持手动登记和外部系统报警火情确认。
2. **人员架构页**：无火情登记权限的其他用户进入；展示自绘组织架构、登录人员及其信息。
3. **沙盘指挥页**：围绕当前火情完成态势、方案、命令、执行反馈和地图作业。
4. **人员与物资管理页**：维护长期人员/中队/物资底账，并查看本次火情快照与缺口。
5. **复盘页**：回放事实、问题分析、根因、整改和经验闭环。

**参谋部、LLM、多 Agent 的工作全部在后台完成。**前台不显示「LLM 增强层」「智脑建议」「参谋部正在工作」等自述或品牌化区域；前台只显示经过业务流程处理后的事实、候选、方案、命令、状态和审计结果。后台仍必须保留来源、产生者、证据、版本和审计链。

## 2. 需求优先级与口径冲突处理

### 2.1 本次新口径为最高优先级

本规划以你 2026-08-25 明确的五页结构和「参谋后台、前台不体现」为当前产品口径。

### 2.2 与旧定版文档的冲突

旧版 02 号文档规定首页直接显示用户提供的组织架构原图；本次新需求明确要求：

- 组织架构由系统自己绘制；
- 不贴图；
- 登录人员直接显示在对应组内，并显示名字和信息。

因此后续应建立新的 **02 号首页 V0.3 需求修订**，替代旧版「原图直接显示」条款。旧图文件和旧锚点实现保留为历史资料，不再作为新首页实现依据。

### 2.3 不能被新需求破坏的工程红线

以下规则继续有效：

- 权力链：`AdvisorProposal → GeneralDecision → ExecutionOrder → Policy/Approval → Executor`；
- `workspace.append_event` 是哈希审计链唯一写入口；
- 校验失败整体降级，禁止猜测、静默补数据或伪造成功；
- 演示数据、模拟轨迹、待接入接口必须显式标注；
- 事实、判断、建议、指令必须分层；
- LLM 只允许做措辞增强，不能新增事实、证据、结论、命令或责任判断；
- 外部系统、物资实时库存、真实气象/水文/无人机数据没有事实源时，页面显示待接入，不编造。

## 4. 五页产品结构

## 4.1 第一页：火情登记页 `/events`

### 页面定位

仅服务于有火情登记权限的人员。页面是火情建档和事件入口，不展示参谋运行状态，不承担沙盘、物资或复盘内容。

### A. 手动登记

保持现有手动登记逻辑和字段：

- 火情名称；
- 报告编号；
- 发现时间；
- 来源；
- 行政位置；
- 等级；
- 行政区；
- 初报；
- 重点目标；
- 可选坐标，未提供时不猜测。

生命周期继续保持：

```text
登记中 → 进行中 → 已升级 → 已关闭
```

手动登记不改变当前权力链：登记、启动、升级、关闭、二维码和进入事件都必须经过现有指挥权限与审计留痕。

### B. 外部系统报警火情

新增「外部报警待确认」区域，外部系统报警不能直接成为正式火情，也不能直接启动处置。

报警记录字段：

- 外部系统名称；
- 外部报警编号；
- 接收时间；
- 原始报警时间；
- 火情名称；
- 位置描述；
- 等级/告警级别；
- 初报内容；
- 重点目标；
- 原始报文摘要与哈希；
- 当前确认状态。

状态：

```text
待确认 → 已确认建档 → 已进入事件
       ↘ 已拒绝
       ↘ 重复/已关联
```

确认动作：

1. 指挥员打开报警详情；
2. 核对来源、时间、位置和初报；
3. 点击「确认建档」；
4. 系统按手动登记同构字段创建 `fire-{序号}` 事件；
5. 保留外部报警编号与正式事件编号的关联；
6. 写入审计链。

拒绝动作必须填写原因；重复报警必须允许关联现有事件，不重复建档。外部报警接入端点仍待平台契约评审，在端点未接入前使用明确的演示/待接入状态，不模拟实时报警。

### C. 权限与落点

| 身份 | `/events` | 登录后首屏 |
|---|---:|---|
| 火情登记权限人员 | 可读写 | `/events` |
| 普通指挥/现场人员 | 不可登记 | `/` 人员架构页 |
| 未登录 | 不可访问 | `/login` |
| 公共屏 | 不进入登记页 | 走独立只读入口 |

## 4.2 第二页：人员架构页 `/`

### 页面定位

这是没有火情登记权限的普通用户登录后的第一页面，也是当前火情的人员组织总览。页面不贴图、不显示参谋运行、不显示 LLM 状态。

### A. 自绘组织架构

采用数据驱动的 DOM/SVG 绘制，不使用组织架构位图：

- 结构数据来自 `org_model.py` 的组、岗位和上下级关系；
- SVG 负责连接线、箭头和稳定布局；
- HTML/SVG 节点负责组名、岗位名、人数和状态；
- 不允许把人员姓名写死在模板；
- 不允许通过图片坐标定位人员；
- 任何节点数据不完整时只显示缺失状态，不猜测岗位或人数。

架构图必须完整覆盖现有组织结构：联合指挥部、前线总指挥、四个副总指挥及专业技术支持、灭火指挥调度、火场维稳管控、后勤综合保障下的全部组和岗位。结构由代码模型生成，不能人工在 HTML 中复制一套第二组织树。

### B. 登录人员直接进入对应组

人员显示来源：长期人员库 + 当前事件名册 + 本次到场快照。

组内人员卡/列表至少显示：

- 姓名；
- 所属单位；
- 固定岗位；
- 本次工作组/岗位；
- 到场状态；
- 到场时间；
- 登录/通信状态；
- 当前任务（无事实源显示暂无数据）；
- 联系方式按权限脱敏。

当前登录人员：

- 在所属组和人员列表中高亮；
- 右侧显示本人详情；
- 已入岗显示当前事件；
- 仅登录未入岗显示待到场，不伪造已到场。

### C. 组节点交互

点击组或岗位节点后，右侧显示该组人员和状态；点击人员后显示详情。移动端使用可滚动、可缩放的自绘图，不裁切、不遮挡节点，不依赖图片锚点。

### D. 权限

普通用户在本页只能查看自己有权限看到的人员和状态，不获得火情登记、事件生命周期、命令、物资写入或复盘写入权限。

## 4.3 第三页：沙盘指挥 `/sand`

### 页面定位

指挥员使用的核心业务页，所有前台内容用态势、对象、方案、命令和执行语言表达。参谋在后台分析，前台不出现「智脑建议」「参谋正在处理」等标签。

### 必须保留的业务能力

- 当前事件、等级、阶段、数据截至时间；
- 当前态势和信息缺口；
- 地图对象与右侧详情双向联动；
- 证据图层与业务图层开关、透明度和来源；
- 火点、火线、危险区、隔离带、队伍、水源、物资点等业务对象；
- 方案比较、指挥员决断、命令确认、执行反馈；
- 异常暂停、重新研判、恢复和撤回；
- 图像导入、配准、候选结果待核验；
- 测距、测面积和保存为草稿业务对象。

### 前台表达调整

| 当前/旧表达 | 后续前台表达 |
|---|---|
| 智脑候选 | 待核验候选/待核验标注 |
| 智脑建议路线 | 建议路线 |
| AI 分析中 | 处理中/待处理，后台来源写入审计但不在业务页自述 |
| 参谋推荐 | 方案比较/推荐方案，显示依据和状态，不显示 Agent 品牌 |
| LLM/AI 卡片 | 删除，不在沙盘页出现 |

候选和建议仍需保留来源、证据、模型/规则版本、产生任务等后台审计字段；前台只展示用户需要判断的业务事实、依据和状态。

## 4.4 第四页：人员与物资管理 `/materials`

### 页面定位

长期底账维护 + 当前事件到场快照 + 物资缺口，不是仓库系统，不是参谋控制台。

### 功能区

1. 长期人员库；
2. 中队及人员编制；
3. 固定岗位与工作组；
4. 中队随队物资；
5. 物资档案；
6. 物资点及库存来源；
7. 当前事件到场人员八态；
8. 当前事件携带物资快照；
9. 可用/消耗/损坏/缺失差异；
10. 缺口分级与补给信息。

长期底账和事件快照必须隔离。无实时物资系统时显示「库存未知/接口待接入」，不显示参谋建议字样，不虚构库存和距离排序。

文件导入继续使用现有预览→草稿→授权发布→回滚链路。Word/Excel/PDF/OCR 等解析引擎未接入前明确标待接入。

## 4.5 第五页：复盘与经验 `/review`

### 页面定位

事后事实回放和闭环工作台，不是 AI 聊天页，也不是报告阅读器。

### 功能区

1. 本次复盘摘要；
2. 时间线回放；
3. 问题分析；
4. 根因分析（事实/因果假设/责任认定严格分开）；
5. 多次火情共性；
6. 整改任务闭环；
7. 经验候选与确认；
8. 趋势统计。

### 前台表达调整

- 「AI 刚产出」改为「待核验候选」；
- 不出现「AI 判断」「参谋正在分析」等状态自述；
- 问题卡显示事实、证据、判断状态、待核验项和分析版本；
- 责任认定不进入任何后台 Agent 输出，也不由规则候选自动生成；
- 复盘负责人权限收紧是后续 A-2，普通指挥员代行结论级动作的演示口径需要移除。

## 5. 五页导航与权限方案

### 5.1 顶部主导航

业务用户只看到以下五个入口，顺序固定：

```text
火情登记｜人员架构｜沙盘指挥｜人员与物资｜复盘
```

不把以下内容作为业务主导航展示：

- LLM/AI/参谋状态；
- 演练控制台；
- 旧的总览、时间线、单独地图入口；
- 后台诊断和开发自检入口。

旧路由短期保留兼容，但从主导航移除，并根据权限做重定向或只读处理。

### 5.2 角色落点

| 角色/能力 | 首屏 | 可见页面 | 可写范围 |
|---|---|---|---|
| 火情登记人员 | `/events` | 五页中按权限开放 | 火情建档、生命周期、名册/二维码等授权动作 |
| 普通指挥/现场人员 | `/` | 人员架构、沙盘、人员物资、复盘的授权只读范围 | 个人入岗/被授权的现场反馈，不可建火情 |
| 复盘负责人 | `/` 或按权限配置 | 复盘写权限 | 复盘结论级动作、整改、经验 |
| 维护人员 | `/` 或按权限配置 | 人员物资维护范围 | 被授权的底账维护 |
| 公共屏 | `/public` | 只读复盘/投屏视图 | 无 |

具体角色名和权限点在实现前需与现有 `GeneralEntryAuth`、成员会话、复盘负责人、维护人员模型统一，不另造第二套权限系统。

### 5.3 参谋后台边界

后台可以继续运行：

- Research/Analysis/Option/RedTeam/Verification 等 Agent；
- LLM 措辞增强；
- 规则候选扫描；
- provider 连通测试；
- 失败回落和 `LLMEnhancementRejected` 审计；
- 工作区事件、版本和哈希链。

但上述内容不作为五页业务界面的可见模块、标题、宣传文案或状态自述。前台只拿后台产生的合规业务结果，并按事实/判断/建议/指令状态展示。

## 6. 分阶段开发计划

### P0：前台口径纠偏与导航冻结

**目标**：先消除当前明确违规项，锁定五页产品骨架。

任务：

1. 从 `/events` 删除「LLM 增强层」卡片和前台自检按钮；
2. 对五页模板做前台文案扫描，移除 AI/参谋自述，只保留业务状态；
3. 固定五页主导航；
4. 按权限修正首屏：有火情登记权限进 `/events`，其他用户进 `/`；
5. 旧 `/map`、`/overview`、`/timeline`、`/drill` 从主导航移除，保留兼容路由；
6. 增加前台禁用词回归检查，防止「LLM 增强层」「智脑建议」「参谋正在」重新出现。

验收：五页导航和首屏角色落点正确；五页页面源码不出现 AI/参谋自述模块；LLM 后台增强和审计测试仍通过。

### P1：火情登记页双来源闭环

**目标**：完成「手动登记 + 外部报警确认」的第一条可用业务闭环。

任务：

1. 保持现有手动登记字段和生命周期；
2. 增加外部报警收件箱数据结构与只读列表；
3. 增加报警详情核对页/区域；
4. 增加确认建档、拒绝、重复关联三种动作；
5. 确认建档复用手动登记同一事件创建逻辑；
6. 外部报警原文摘要、哈希、来源和关联编号入审计链；
7. 未接入真实外部端点时使用本地假消息测试，不声称实时接入。

验收：手动和外部确认最终生成同构事件；拒绝不建档；重复可关联；事件生命周期和权限不回退。

### P2：人员架构页从贴图改为自绘

**目标**：完成普通用户首屏和自绘组织架构。

任务：

1. 修订 02 号首页需求文档为「数据驱动自绘」版本；
2. 将 `org_model.py` 的组、岗位、上下级关系整理为唯一结构数据；
3. 新增自绘布局模型，生成稳定节点位置和连线；
4. 删除运行时对 `org_chart.png`、`org_anchors.json` 的依赖；
5. 节点内显示组名/岗位/编制与到场概览；
6. 登录人员按本次事件名册和签到事实进入对应组；
7. 点击节点显示人员姓名、单位、岗位、到场、通信和联系方式；
8. 当前登录人员高亮；
9. 普通用户权限过滤和手机号脱敏；
10. 移动端缩放、滚动和节点点击。
