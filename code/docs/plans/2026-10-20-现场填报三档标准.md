# 现场填报三档标准（用户确认 2026-10-20）

> 总原则（用户原话）：**逻辑简单、一目了然。**
> 系统已经知道的内容，不要让用户再看一遍；用户只做决定。

## 1. 原则

**现场不"填表"，只"确认"。**

系统里已经有缺项、区域、责任人、时限这些信息，不该让人再打一遍。
表单的默认形态必须是：**内容已填好，按钮上写清发给谁、什么时候要，人只负责点头。**

## 2. 三档

| 档 | 什么时候用 | 界面形态 | 交互次数 |
|---|---|---|---|
| **一键** | 内容就是系统已有的那条（大多数情况） | `安排补查 → 李四 · 30分钟内` | 1 次点击 |
| **改一项** | 只差一个字段（换责任人/改时限） | 点「改」只露出那一个字段，就地改，不弹大表单 | 2–3 次 |
| **手工填写** | 真正新造一件事，没有现成内容可带 | 完整表单，**默认折叠** | 多 |

反例（改造前）：不管什么情况都直接给第三档，4 个必填 + 勾选 + 提交。

## 3. 能预填 / 不能预填（硬线）

| 可以预填 | 绝不能预填 |
|---|---|
| 缺项内容、区域、时限 | 专业判断结论 |
| 责任人（从可派名单取，按钮上写明是谁） | 核验是否通过 |
| 业务标题、完成标准 | 风险等级、责任认定 |
| 技术字段（版本号、请求号） | 是否采纳某方案 |

**预填是省打字，不是替人做决定。** 破了这条，系统的"人负责"就不成立。

## 4. 提交前必须给一句摘要

例：`发给李四 · 30分钟内 · 补查气象观测`

要求：念得出来、看得懂、能据以判断"发出去对不对"。

## 5. 手机/手套场景

- 主按钮高度 ≥ 40px（沿用项目既有的 44px 触控约定）
- 一屏内不需要滚动就能点到主按钮
- 长文本用"选"代替"写"：从已有缺项、预案、名单里选

## 6. 需要改造的表单（按现场频率）

1. 任务发布 / 接收 / 回执
2. 执行反馈、核验关闭
3. 物资实收、调拨、耗损
4. 复盘问题登记、整改
5. 人员状态标记

已完成：
- **侦查请求（安排补查）**：一键派发，按钮写清责任人；完整表单折叠为「改一项或手工填写」，
  且**展开即已预填**（缺项文本、区域、首位责任人、30 分钟时限），去掉原"确认收集内容…后派发"的重复勾选
- **任务接收（任务已送达 / 我已查看 / 确认接收）**：三个动作各成一键按钮，说明按动作预置；
  原「选动作 + 手写说明」表单折叠为「改一项或手工填写」，隐藏字段、请求号、版本、CSRF 全部不变
- **九步走的"下达核验指令"**：原来 7 个输入框（范围/情况/依据/遗留/跟进/结果/核验人）→
  现在只剩 **2 个下拉（下给谁、结果）+ 1 个按钮**；其余内容由系统带着（隐藏字段），
  顶部给一句摘要「要下达：火线与通道研判，仅本轮模拟范围」

## 7. 验收口径（每张表单都要演示这三条）

1. 主路径一键完成，不出现空白必填项
2. 改一项时只露一个字段
3. 手工填写默认折叠，展开后原有校验与审计不变
