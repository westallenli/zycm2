# 复盘与经验页定版 V0.2

> 页面路径：`/review`
> 职责：事后分析工作台。回放事实 → 找问题 → 定位根因 → 识别共性 → 确认定责边界 → 生成整改 → 跟踪闭环 → 沉淀经验 → 反哺研判。
> 定位：不是报告阅读器，不是 AI 聊天页。

## 1. 页面区域

顶部：当前事件、事件状态、复盘状态、数据截至；含范围筛选（当前火情 / 选定多次 / 同类 / 同区域 / 同季节 / 全部）。

五个工作区：

1. 本次复盘
2. 时间线回放
3. 问题分析
4. 多次火情共性
5. 整改与经验

## 2. 本次复盘

- 事件摘要：发现/上报/前指成立/首批到场/首态势/首命令/主要阶段/异常/复燃/结束/总时长。
- 摘要区分数据状态：系统记录 / 人工补录 / 外部系统 / 模拟数据 / 待核验；缺失明确标注，不补写。
- 计划与实际对比表：队员到场、首次侦查、火线确认、首批命令、水泵接力、任务反馈等，差异只表偏差，不等同责任。

## 3. 时间线回放

- 包含：报警、扫码入岗、中队到场、信息上报、图像导入、候选标注、核验发布、态势版本、方案、决断、命令下达/接收、执行进度、异常暂停、重新研判、恢复/撤回、完成、撤离、物资消耗、结束、复盘意见。
- 每条显示：发生/接收时间、来源、操作者、关联对象、状态、是否确认、证据。
- 点击联动当时地图态势、火线版本、队伍位置、人员物资、方案、命令、反馈。
- 不用事后信息反推指责当时决策。

## 4. 问题分析

### 4.1 问题产生

触发方式：计划/实际偏差、异常回放、规则核验、跨对象冲突。智脑只产候选问题，每条带证据。

### 4.2 问题卡片字段（细化）

问题卡片分「标识、事实、判断、状态」四组字段，事实与判断不混在同一栏。

#### A. 标识字段

| 字段 | 说明 |
|---|---|
| 问题编号 | 唯一 id，如 `ISSUE-2026-0317-07`，稳定不变，历史保留 |
| 问题标题 | 一句话可读描述 |
| 问题类型 | 指挥 / 作战 / 信息 / 资源后勤 / 通信 / 安全协同（单选主类，可附次级标签） |
| 所属阶段 | 接警启动 / 侦查 / 态势 / 调配 / 方案 / 命令 / 执行 / 异常 / 收尾 |
| 关联事件 | eventId，与共性规律引用的多事件区分 |

#### B. 事实字段（有证据支撑，只描述发生）

| 字段 | 说明 |
|---|---|
| 触发依据 | 计划/实际偏差 / 异常 / 规则 / 冲突，标注由哪条规则或哪组数据触发 |
| 问题描述 | 客观描述发生了什么 |
| 首次发生时间 | 首次观测到的时间点 |
| 持续时长 | 起止与时长；仍在持续标「进行中」 |
| 影响对象 | 具体工作组 / 中队 / 物资 / 任务 / 态势版本 |
| 证据列表 | 每条证据含：编号、类型、时间、是否已核验、可点击跳转 |

#### C. 判断字段（智脑推断，需人工确认）

| 字段 | 说明 |
|---|---|
| 影响范围 | 局部 / 多组 / 全局（推断，标记） |
| 严重程度 | 低 / 中 / 高 / 关键（见 4.3 分级） |
| 根因假设 | 链接到第 5 节的结构化根因，不内联长文本 |
| 待核验项 | 结论成立前需人工确认的事实清单 |
| 置信度 | 见 4.4 |
| 分析版本 | ruleVersion + modelVersion，可追溯到哪套规则/模型产出 |

#### D. 状态字段

| 字段 | 说明 |
|---|---|
| 审核状态 | 待核验 / 已确认 / 已修订 / 不成立 / 已转整改 / 已关闭（见 4.5） |
| 关联问题 | 同源或连锁的其他问题 id，用于组合定位 |
| 更新时间 / 操作者 | 最后变更人与时间 |

### 4.3 分组与排序（细化）

#### 分级定义

| 级别 | 颜色 | 判据 |
|---|---|---|
| 关键 | `#B84A42` 红 | 可能影响人员安全或火势失控的关键延误/遗漏 |
| 重要 | `#B77A1A` 橙 | 影响处置效果或方案执行 |
| 一般 | `#B77A1A` 黄 | 影响效率或信息质量 |
| 观察项 | `#647382` 灰 | 暂无明确影响，建议关注 |

> 关键与重要用红/橙区分；一般与观察项用弱化色，避免整页黄橙堆叠。

#### 默认排序

1. 第一优先级：严重程度（关键 → 重要 → 一般 → 观察项）；
2. 第二优先级：影响范围（全局 → 多组 → 局部）；
3. 第三优先级：首次发生时间（早 → 晚）；
4. 同分项按问题编号稳定排列，保证每次打开顺序一致。

#### 分组视图

- 按阶段：接警/侦查/态势/调配/方案/命令/执行/异常/收尾；
- 按类型：指挥/作战/信息/资源后勤/通信/安全协同；
- 按对象：工作队/物资/任务/态势版本；
- 按审核状态：待核验/已确认/已转整改/已关闭。

#### 筛选

- 支持按类型、阶段、严重程度、影响范围、审核状态、时间区间组合筛选；
- 支持关键字搜索标题与描述；
- 筛选条件与结果可保存为「视图」。

#### 联动

点卡片右侧联动：证据面板、根因假设、待核验项、关联问题链、时间线定位。

### 4.4 置信度规范

置信度只描述「该判断有多大把握」，不替代「是否已核验」。两条互相独立。

#### 分级

| 置信度 | 含义 |
|---|---|
| 高 | 证据充分，直接形成结论 |
| 中 | 部分证据，存在待核验项 |
| 低 | 证据弱或冲突，仅作线索 |

#### 呈现规则

- 每条判断单独标注置信度，不与整卡共用；
- 高置信度但未核验，仍标「待核验」，不得因置信度高自动通过；
- 低置信度但被人工确认，显示「已确认（低置信度）」，保留原始置信度不覆盖；
- 证据不足时置信度不显示为高。

### 4.5 审核状态

#### 状态集合

| 状态 | 含义 | 触发 |
|---|---|---|
| 待核验 | AI 刚产出或条件变化，等待人工 | 初始 / 新证据进入后重置 |
| 已确认 | 负责人确认问题成立 | 负责人核验通过 |
| 已修订 | 负责人修改描述/分级/取证后确认 | 人工编辑保存 |
| 不成立 | 证据不足或判断错误被否决 | 负责人否决，须附理由 |
| 已转整改 | 已生成关联整改任务 | 整改任务建立并关联 |
| 已关闭 | 处理完成或无后续动作 | 负责人关闭，须附关闭原因 |

#### 状态流转

```text
待核验 → 已确认 / 已修订 / 不成立
已确认 → 已转整改 → 已关闭
已修订 → （重新核验）已确认
不成立 → 已关闭（保留原因）
任意已关闭 → 新证据进入 → 重新打开为待核验
```

- 每次流转记录操作者、时间、原因；
- 已关闭问题不删除，历史可查；
- 新证据进入时相关问题自动回到「待核验」并通知负责人。

## 5. 根因分析（非定责）

### 5.1 三类结论边界

| 类型 | 说明 | 谁产生 |
|---|---|---|
| 事实 | 有证据支撑，确实发生 | 系统/证据 |
| 因果假设 | 智脑推断，需验证 | 智脑（候选） |
| 责任认定 | 定责结论，永不入 AI 输出 | 仅复盘负责人 |

### 5.2 根因假设结构（细化字段）

| 字段 | 说明 |
|---|---|
| 假设编号 | 唯一 id，可被多个问题卡片引用 |
| 原因假设 | 一句话说明推测原因 |
| 支持证据 | 证据列表，逐条可跳转 |
| 相关性强度 | 强 / 中 / 弱，标注属相关而非因果 |
| 反例 | 不支持该假设的样本/事件 |
| 待验证事实 | 需补充什么才能从「相关」升为「因果」 |
| 置信度 | 高/中/低（见 4.4） |
| 结论状态 | 待验证 / 已验证 / 不成立 |

### 5.3 因果纪律

- 只表述「相关」，不得把相关写成因果；
- 从「相关性」到「因果」必须补足待验证事实；
- 责任认定与根因假设隔离展示，不写进 AI 卡片。

## 8. 整改闭环（细化）

### 8.1 整改任务字段

| 字段 | 说明 |
|---|---|
| 整改任务编号 | 唯一 id，如 `RECT-2026-0317-03` |
| 关联问题/共性 | 引用问题 id 或共性规律 id（可多个） |
| 整改措施 | 具体动作，可包含多条 |
| 责任单位 / 责任人 | 明确到岗到人 |
| 优先级 | 高 / 中 / 低 |
| 完成期限 | 日期 |
| 验证方式 | 用什么事实判定「已整改」 |
| 关联事件 | 来源事件 |
| 当前状态 | 见 8.2 状态机 |
| 更新时间 / 操作者 | 最后变更人与时间 |

### 8.2 状态机

```text
待分派 → 整改中 → 待验证 → 已完成 → 已关闭
              ↘ 验证未通过 → 整改中（重新整改）
```

- 超期：超过完成期限仍未到「待验证」即高亮提醒，进入责任单位待办；
- 关闭后改动：需重新打开并记录重开原因，不静默修改；
- 每次状态流转记录操作者、时间、原因。

### 8.3 复现跟踪

- 后续事件再出现同一问题，该系统标记为「整改后复现」；
- 新问题链回原整改任务，原任务进入「复现待评估」提示；
- 用于识别「改了没用」，触发重新评估措施，而非简单关闭。

## 6. 共性规律（多次火情）

- 样本筛选：时间、区域、规模、响应等级、处置时长、天气、地形、是否复燃、是否用无人机、是否通信异常、是否调用外部物资点。
- 样本质量：纳入 / 数据缺失(标缺失字段，降权) / 排除(记原因)。
- 聚合维度：高频、同阶段、高影响、整改后复现、区域/类型特征、连锁规律。
- 共性规律卡：出现次数、样本占比、涉及阶段、平均影响、最早/最近出现、趋势、关联经验、整改状态。

## 7. 趋势与统计口径

指标公开口径：名称、计算方法、样本数量、缺失处理、时间边界。
典型指标：首态势形成时长、队伍平均到场时长、命令接收率、任务按时完成率、异常任务占比、反馈缺失率、物资缺口频次、通信异常影响时长、复燃处置时长。
不做黑盒综合评分，必须可下钻到事实。

## 8. 整改闭环

- 字段：关联问题/共性、措施、责任单位/人、优先级、期限、验证方式、关联事件。
- 状态机：待分派 → 整改中 → 待验证 → 已完成 → 已关闭；验证未通过回到整改中；超期高亮；关闭后改动需重开并记原因。
- 复现跟踪：后续事件再出现同一问题，标记「整改后复现」并链回原任务，识别「改了没用」。

## 9. 权限与审核

矩阵（查看 / 问询 / 确认问题 / 修订结论 / 定责 / 转整改 / 发布经验）：

- 复盘负责人：全权
- 指挥员：查看、问询、确认本事件问题、建议
- 智脑：分析读取、生成候选、建议（不确认、不定责、不发布）
- 授权维护人员：查看、问询、建议
- 普通到场人员：本人相关、问询
- 公共屏：已发布摘要

### 审核关卡

AI 候选问题 → 负责人核验 → 确认/修订/否决
AI 根因假设 → 证据验证 → 确认或降为待验证
经验候选 → 负责人确认 → 进正式经验库
定责 → 仅负责人手工形成
整改任务 → 负责人发布

### 智脑硬约束

✗ 自动定责 ✗ 假设写成事实 ✗ 自动发布整改 ✗ 经验直入知识库 ✗ 事后反指责 ✗ 无证据补写。

## 10. 经验沉淀

- 三态：经验候选 / 已确认 / 已失效。
- 字段：内容、适用条件、来源事件、验证次数、最近验证、有效期、失效条件、确认人。
- 引用标注：沙盘引用经验须显示来源、适用条件、是否有效、是否匹配。
- 经验不覆盖当前事实、正式命令、审计记录。

## 11. 复盘问询

- 只读不改，覆盖本次与多次对比问题。
- 回答带：结论、数据范围、引用事件、证据链接、统计口径、未纳入数据、置信度；证据不足明确说明。
- 语音沿用沙盘问询引擎，同数据同权限过滤。
- 语音若识别出命令意图，复盘页一律不执行，只提示「复盘页为分析视图，不支持下达命令」（与沙盘命令转草稿机制区分）。

## 12. 报告与导出

状态：AI 草稿（缺证据标未核实）→ 人工编辑 → 待审核 → 已发布 → 已归档。
内容固定：事件概况、组织到场、态势变化、决策时间线、方案命令、执行反馈、异常、计划/实际差异、指挥问题、作战问题、物资通信问题、AI 候选、人工确认结论、整改任务、经验沉淀。
当前：页面查看 + Markdown/打印导出；Word/PDF 后续预留。
版本：新证据 → 新版本 → 保留旧版 → 重新审核；历史不静默覆盖。

## 13. 状态机

处置中 → 事件结束 → 待生成复盘 → AI 草稿 → 负责人审核 → 人工补录 → 确认问题 → 转整改 → 确认经验 → 发布复盘 → 归档；新证据 -> 升版本 -> 重新审核。

## 15. 最终闭环

```text
火情结束 → 汇总留痕 → 重建时间线 → 计划/实际对比
→ 识别指挥/作战/信息/物资/通信/安全问题
→ 根因假设(非定责) → 多次对比找共性
→ 人工审核问题与经验 → 整改任务 → 跟踪效果
→ 识别整改后复现 → 沉淀经验 → 反哺后续研判
```

## 16. 四页职责总览

```text
/login   确认谁进入本次事件
/        看清组织和人员到场
/sand    态势、决策、命令、执行闭环
/review  问题、共性、整改、经验闭环
```
