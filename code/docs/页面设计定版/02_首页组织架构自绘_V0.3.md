## 0. V0.2 → V0.3 变更摘要

| 条目 | V0.2 | V0.3 |
|---|---|---|
| 结构唯一来源 | 用户提供的原始 PNG 图 | `panda_brain/org_model.py` 结构数据（指挥节点 + 岗位槽位 + 隶属关系），代码即事实源 |
| 呈现方式 | 原图完整显示 + 框外叠加 | 系统自绘节点与连线（HTML + 内联 SVG），无任何图片 |

| 动态层位置 | 只能在原图外部或空白处 | 直接呈现在节点内部（编制、到场概览、登录人在组标记） |

## 1. 核心约束（不可回退）

- 组织结构的唯一来源是 `org_model.py` 的结构数据：
  - `COMMAND_NODES`：8 个指挥节点及其上下级（joint → general → 六条线）；
  - `POSITION_SLOTS`：32 个一线组槽位（含编制上限 `max_headcount`）；
  - `_DOMAIN_PARENT`：领域 → 副总指挥/调度长/发言人的隶属关系。
- 页面必须由这些数据**自绘**生成节点与连线；禁止读取、引用任何组织架构图片或锚点文件。
- 不得增删合并改写任何岗位；页面上的组名与代码数据逐字一致。
- 布局由确定性布局模型生成（纯函数、固定像素数学）：同一数据两次渲染结果完全一致，节点与连线无重叠遮挡。

## 2. 结构内容（与 V0.2 §2 相同的名录，来源改为代码数据）

- 联合指挥部/工作组 → 前线总指挥（属地行政首长、总负责）；
- 总指挥下辖六条线：调度长（综合协调）、新闻发言人、副总指挥·专业技术支持、副总指挥·灭火指挥调度、副总指挥·火场维稳管控、副总指挥·后勤综合保障；
- 各线下属组共 32 个（二期 PRD 口径 29 + 新闻发言人下属 3 个 subgroup）（专家支持组…场地组），全名录见 `org_model.py POSITION_SLOTS`，本文件不复制副本以免两处失同步。

## 3. 节点内呈现与交互

### 3.1 组节点（32 个）

| 元素 | 说明 |
|---|---|
| 组名 | `PositionSlot.name` 原文 |
| 编制 | `编制 N`（N = `max_headcount` 上限） |
| 到场概览 | 已配置名册时显示 `实到/应到` 角标（绿＝满员到齐、黄＝部分、灰＝无人）；未配置名册时如实显示「名册未配置」，不虚构数字 |
| 登录人在组 | 当前登录人按**本次事件名册指派或有效签到绑定**落入对应组：节点描边高亮，节点内显示「姓名（我）」；仅名册指派未刷码时标注「（我·未到场）」 |

### 3.2 指挥节点（8 个）

显示职务名称原文与下属组数；无常设人员槽位的不虚构人数；已配置名册时附带本线到场合计。

### 3.3 点击节点

点击任意节点，右侧面板显示（沿用 V0.2 §5.1 字段）：

- 组名 / 节点名；
- 人员姓名、单位、固定岗位、工作组—本次岗位；
- 到场状态（含八态判定态如实叠加，预编入/待到场仍显示「未到场」）；
- 到场时间；当前任务（无数据源如实标「—」）；
- 通信状态：统一「待接入」，不虚构在线/离线；
- 联系电话（按 §4 脱敏）。

### 3.4 状态词汇

沿用 V0.2 §3.2/§3.3 与 doc 04 八态口径，不换词；状态色沿用全局色板（唯一灰 `#647382`）。

## 4. 联系方式脱敏（不变）

| 角色 | 显示 |
|---|---|
| 指挥员 | 完整号码 |
| 到场人员（本人） | 本人完整号码 |
| 到场人员（他人） | 中间四位打码 |
| 公共屏 | 全部打码 |

## 5. 数据来源（不变 + 收紧）

- 长期人员库 + 本次名册 + 有效签到绑定 + 八态推导，单一事实源 `personnel_states.derive_personnel_states`；
- 不做本地伪数据；无名册、未导入、待接入均显式标注；
- **新增**：渲染为纯函数，绝不改写工作区（GET 只读由调用方 version 比对兜底）。

## 6. 自绘布局与端侧适配

- 列结构：六条线各占一列，列内组卡竖排；联合指挥部与前线总指挥居中置顶；
- 连线：SVG 直线层（总指挥→横向分配母线→各列下垂线→列内脊线），绘制于卡片层之下；
- 画布固定像素尺寸置于可滚动容器内；提供缩放控制（0.55–1.3 档位），移动端横向滚动 + 缩放可用；
- 窄屏（≤900px）侧栏折行至画布下方。
