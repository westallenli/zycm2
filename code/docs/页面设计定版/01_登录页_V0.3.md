# 登录页功能定版 V0.3

> 页面路径：`/login`（登录）＋ `/events`（火情登记与管理，指挥态）
> 职责：身份认证 + 火情事件管理入口 + 现场二维码刷码入岗。只做认证与入岗，不承载业务内容。
>
> 本版依据《森林草原火灾前指决策辅助平台_增强版PRD》§13.3「固定人员扫码自动入岗」及《对外数据接口规范》FIRE_EVENT / ORG_MEMBER_ONBOARDING 对齐修订。

## 1. 页面定位

- 登录页三区：**指挥员登录**（用户名+口令）、**人员登录**（个人账号+口令）、**刷码确认**（人员登录后出现）。
- 支持多火情并存：登录与刷码都绑定「当前事件上下文」；二维码按事件签发，互不通用。
- 登录页不显示地图、物资、方案、AI 对话、组织架构。
- 未登录人员不能进入首页、沙盘、物资、复盘页面；公共屏另走免登录只读入口。

## 2. 账号体系

| 角色 | 凭证 | 说明 |
|---|---|---|
| 指挥员 | 用户名 + 口令 | 单一管理员账号 `admin`，口令沿用现有解析链（启动参数/环境变量/演示常量）。多账号与角色细分随权限体系后续版本。 |
| 现场人员 | 个人账号 + 口令 | 账号＝长期人员库手机号（唯一键复用）；初始口令统一为 `123456`，界面标注「演示初始口令」。正式版接统一认证后替换。 |

- 人员使用个人账号登录，**不通过扫码选择岗位**（PRD §13.3 第 2 步）。
- 会话记住身份：刷码时不再输入任何身份信息（废除 V0.2 的手机号输入项）。

### 2.1 登录会话字段

| 字段 | 说明 |
|---|---|
| 会话令牌 | 认证后签发，携带权限与失效时间 |
| 角色 | commander / member |
| 姓名 / 账号 | 来自长期人员库或指挥员账号 |
| 绑定事件 | 人员入岗后锁定的事件 eventId；空＝尚未入岗 |
| 到场时间 | 刷码确认成功自动写入 |
| 登录渠道 | 账号密码（本期）；已绑定设备后续版本 |

## 3. 火情事件管理（多火情）

### 3.1 事件录入

两条来源，字段同构：

| 来源 | 说明 |
|---|---|
| 页面录入 | 指挥态表单登记新火情 |
| 外部系统接入 | `ingest_fire_event()` 接口函数，按《对外数据接口规范》FIRE_EVENT 消息；HTTP 端点本期标注「待对接」 |

### 3.2 事件字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 事件编号 eventId | 自动生成 | `fire-{序号}` |
| 名称/编号 | 是 | 火情名称与报告编号 |
| 发现时间 | 是 | ISO 本地时间 |
| 来源 | 是 | 页面录入 / 接入系统名称 |
| 位置 | 是 | 行政位置描述 |
| 状态 | 自动 | 见生命周期 |
| 等级 / 行政区 / 初报 / 重点目标 | 否 | 选填，接口可后补 |

### 3.3 事件生命周期

```text
登记中 → 进行中 → 已升级 → 已关闭（归档）
         └──────────────────────┘
```

- **登记中**：建档未启动；不可签发二维码、不可刷码入岗。
- **进行中**：指挥员「启动处置」后进入；可配置名册、签发二维码、人员入岗。
- **已升级**：火情升级标记，仍可入岗。
- **已关闭**：归档只读；不可签发、不可入岗，历史全部保留。
- 每事件一个独立任务空间（独立快照文件）；一人同一时间只能绑定一个事件。
- 指挥员登录成功后落地 `/events` 火情管理页：列表（状态章）＋ 录入表单 ＋ 行操作（进入 / 签发二维码 / 撤销 / 启动 / 升级 / 关闭）。

## 4. 现场登录与扫码入岗流程（PRD §13.3 对齐）

```text
准备阶段（指挥员）：
  火情登记 → 启动处置（进行中）→ 配置本事件名册 → 为当前火情签发入场二维码

现场（人员）：
  个人账号登录 → 输入/扫描火场二维码编号（码只识别事件，不含身份不含岗位）
→ 系统按本事件名册读取预配置岗位关系
→ 提示「即将进入：某工作组—某岗位」→ 本人确认
→ 写入到场记录 → 进入该事件工作空间（首页 /）
```

- 二维码只识别火情事件/前指任务空间；身份来自登录会话，岗位来自预配置名册。
- 演示环境无摄像头：以输入「二维码编号」等效扫码，界面照实标注「演示刷码方式」。

### 4.1 本事件名册（预配置）

- 指挥员从长期人员库逐人勾选加入，或「全部加入」；岗位按本职（home_position）自动解析为编制槽位作为默认建议，可人工修改。
- 名册是**提前维护的授权清单**，区别于花名册（实际入岗结果）。
- 未配置名册的进行中事件不允许刷码入岗，提示「本事件名册未配置」。

### 4.2 重复扫描幂等（修正 V0.2 口径）

- 已在岗人员再次刷码：**直接送回该事件工作空间**，不报错、不重复写到场记录（PRD §13.3 第 6 步「幂等更新」）。
- 已在岗但会话丢失（如服务重启）：补发会话，同样不重复写记录。
- V0.2 的「重复登录报错」口径废止。

## 5. 二维码规则

- 一枚事件码只绑一个 eventId；多火情各自签发、互不通用；码不含岗位、不含个人身份。
- 只有「进行中／已升级」的事件可签发；签发与撤销是指挥员授权动作，落审计链。

### 5.1 二维码对象字段

| 字段 | 说明 |
|---|---|
| 二维码编号 | 唯一 id（`qr-{序号}`，按事件空间编列） |
| 事件编号 / 事件名称 | 绑定的事件 |
| 前指任务空间 | 扫码后进入的空间 |
| 状态 | 有效 / 已过期 / 已撤销（过期查询时现算） |
| 有效期起 / 止 | 默认 72 小时，到期重签，不自动续期 |
| 生成人 / 生成时间 | 审计 |
| 撤销人 / 撤销时间 | 作废记录，历史保留 |

## 6. 身份匹配结果

| 结果 | 处理 |
|---|---|
| 匹配成功（在本事件名册且岗位可解析） | 提示「即将进入：某工作组—某岗位」→ 本人确认 → 入岗 |
| 已在岗（含会话丢失） | 幂等：直接回该事件工作空间，不重复记录 |
| 不在本事件名册 | 「身份异常待处理」转人工；不允许自行改岗 |
| 已绑定其他事件 | 跨事件冲突，转人工处理 |
| 岗位无法解析到编制槽位 | 「身份异常待处理」转人工 |
| 二维码失效 / 已撤销 / 已过期 | 明确提示，向指挥部获取新码 |
| 账号不在长期人员库 | 转人工补录，不静默放行 |
| 信息过期 | 提示更新后方可入岗 |

## 7. 成功跳转

- 人员入岗成功 → `/` 该事件首页原图，自动高亮当前登录人员并显示信息。
- 人员仅登录未刷码 → 停留登录页「待到场」卡，显示刷码输入框。
- 指挥员登录成功 → `/events` 火情管理页。

## 8. 登录状态与错误提示

必须覆盖：

- 用户名/密码错误
- 二维码失效 / 过期 / 已撤销
- 人员不在当前事件名册 / 名册未配置
- 跨事件冲突（已绑定其他事件）
- 账号锁定
- 会话过期
- 服务不可用
- 已在岗——返回事件（幂等提示，非错误）
- 登录成功 / 退出登录

### 8.1 状态定义

| 状态 | 说明 |
|---|---|
| 待认证 | 已提交凭证或刷码，等待核验 |
| 认证中 | 二次确认/人工核验中 |
| 已认证（未入岗） | 人员登录成功但未刷码确认 |
| 已入岗 | 刷码确认完成，绑定事件 |
| 锁定 | 连续失败或人工锁定，需解除 |
| 会话过期 | 令牌超时，重新登录 |
| 已退出 | 主动退出 |
| 服务不可用 | 认证服务不可达 |

### 8.2 状态流转

```text
待认证 → 认证中 → 已认证（未入岗）→ 刷码确认 → 已入岗 → 已退出
待认证 → 待认证（失败重试）
认证中 → 待认证（取消）
已认证（未入岗）→ 会话过期 → 待认证
已入岗 → 再次刷码 → 已入岗（幂等）
多次失败 → 锁定 → 解除 → 待认证
```

## 9. 权限边界

- 登录页是真实认证门（fail-closed）：任何无法验证的状态一律阻断，不伪造成功，不降级放行。
- 锁定态与指挥态贯穿全部页面；未登录访问业务页一律拦截；公共屏另走免登录只读入口。
- 人员会话只读业务页，无任何命令面；command_mode 永远只属于指挥员秘钥会话，权力链不因扫码回退。
