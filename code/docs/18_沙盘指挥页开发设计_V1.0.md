# 沙盘指挥页开发设计 V1.0

> 版本：V1.0  
> 日期：2026-08-26  
> 适用工作区：`D:/熊猫开发项目/熊猫智脑cola v4`  
> 对应页面：`/sand`  
> 文档性质：开发设计与验收依据，不是当前实现说明。

---

## 1. 设计结论

沙盘指挥页的核心不是问答、表格或功能集合，而是：

> **真实地图作为现场事实主画面；指挥助手负责目标、请示、方案和回报；方案推演区负责方案比较与地图推演；执行回执回到地图；正式态势、推演态势和候选观察严格分层。**

页面主线：

```text
司令提出目标
  → 参谋后台收集与分析
  → 发现信息缺口并申请收集
  → 新信息进入地图观察/候选层
  → 形成三套应急预案
  → 右下方案区比较与地图推演
  → 司令采纳、修改、否决或自提方案
  → GeneralDecision
  → ExecutionOrder
  → Policy / Approval
  → 执行人任务与回执
  → 地图更新执行观察
  → 独立核验
  → 指挥助手汇报结果
```

参谋可以自动执行后台的信息收集、分析、方案形成、命令编制、过程跟踪和结果核验；任何改变现场现实或正式决策的动作，仍必须经过司令明确决断、命令确认和既有权力链。

## 2. 范围与边界

### 2.1 本页负责

- 当前事件的真实地图展示；
- 本地地图与无人机侦查图片覆盖；
- 司令手动标注点、线、面和路线；
- 当前任务、信息缺口和参谋请示；
- 应急预案生成、比较、修改和地图推演；
- 决断确认、命令准备、执行反馈和结果核验摘要；
- 地图对象、方案、命令、回执之间的空间联动；
- 当前事件范围内的审计摘要。

### 2.2 本页不负责

- 长期人员库和物资底账维护；
- 外部报警建档；
- 完整复盘台账编辑；
- 完整无人机影像生产、分析或视频流工作台；
- 技术模型、Agent 名称、推理过程和 LLM 运行状态展示；
- 参谋绕过司令自动改变外部现实。

人员、物资、报警和复盘页面向沙盘提供当前任务所需的摘要，不在沙盘复制完整维护表单。

### 2.3 工程红线

- 权力链固定为：`AdvisorProposal → GeneralDecision → ExecutionOrder → Policy/Approval → Executor`；
- `workspace.append_event` 是哈希审计链唯一写入口；
- 参谋提议不等于司令决断，方案采纳不等于命令下达，执行人自报完成不等于独立核验完成；
- 新信息只能自动新增观察、候选或过程状态，不能静默改写司令已发布的正式火线、危险区、重点目标或正式命令；
- 所有自动处理必须保留来源、时间、版本、依据和产生者；
- 资料缺失、坐标不明、执行结果未知时 fail-closed，不猜测、不补造、不宣称成功；
- 演示数据、模拟执行和待接入接口必须显式标注。

| 区域 | ≥1440px | 1200-1439px | 900-1199px | <900px |
|---|---:|---:|---:|---:|
| 顶部状态条 | 48-52px | 48-52px | 48-52px | 48-56px |
| 左侧工具栏 | 48-56px | 48-56px | 48-56px | 底部工具条 |

右侧工作区两个区域独立滚动：标题、任务摘要、输入框和底部操作栏固定；消息列表和方案列表分别滚动。

### 3.3 顶部状态条

固定显示：

- 事件名称、编号、等级和事件状态；
- 当前任务摘要；
- 当前阶段；
- 地图名称、版本、更新时间；
- 当前影像时间或最新覆盖层；
- 待处理申请、待决断事项、异常数量；
- 通信和外部数据源状态。

不显示：模型名称、Agent 数量、内部推理状态、LLM 状态卡或“参谋正在思考”等技术自述。

### 3.4 左侧地图工具栏

工具按一个主操作模式工作，每次只能有一个绘制或编辑工具处于激活状态：

1. 选择/查看；
2. 图层；
3. 火点；
4. 火线；
5. 危险区/隔离带；
6. 路线/箭头；
7. 队伍位置；
8. 指挥部；
9. 水源；
10. 物资点；
11. 测距/测面；
12. 无人机影像覆盖；
13. 地图数据与影像导入；
14. 撤销/重做。

工具栏收起时使用图标和 tooltip；进入绘制、影像覆盖或方案推演模式时，地图顶部显示当前模式和“完成/取消/退出”操作。

## 4. 真实地图与图层模型

### 4.1 地图层级

从下到上固定为：

```text
本地基础地图
  → 无人机影像覆盖层
  → 已发布正式态势
  → 人工草稿/待核验候选
  → 执行回执观察层
  → 方案推演层
  → 当前选择高亮层
```

地图右上角必须显示当前视图：

```text
正式态势
```

或：

```text
方案 A-v2 推演 · 非正式执行态势 · 依据截至 09:42
```

### 4.2 本地优先

第一版地图以本地底图为优先，在线地图只能作为可选补充。地图加载失败时显示“地图数据不可用”，不能静默退回容易被误认为真实地图的示意图。

底图与业务叠加数据分离：

- 底图提供道路、河流、行政区、地形、重点目标等基础信息；
- 影像层提供无人机侦查证据；
- 业务层提供火点、火线、危险区、队伍、路线、资源、命令和回执；
- 更新某层不得覆盖其他层。

### 4.3 图层显示规则

| 样式 | 业务含义 |
|---|---|
| 高亮实线 | 已发布正式态势 |
| 虚线半透明 | 草稿或待核验候选 |
| 橙色 | 执行回执观察，尚未独立核验 |
| 斜线纹理 | 方案推演对象 |
| 灰色 | 历史、失效、撤回 |
| 红色 | 安全异常或越界 |
| 带影像角标 | 关联无人机影像证据 |

## 5. 无人机图片覆盖

### 5.1 产品口径

地图导入不是重新替换基础地图，而是把无人机侦查图片作为影像证据层覆盖到当前本地地图上。第一版以**快速粗略覆盖**为目标，不强制高精度 GIS 配准。

粗略覆盖必须显式显示：

```text
无人机影像 · 粗略覆盖
来源：无人机一号
采集时间：09:42
定位方式：人工估算
不能作为精确坐标依据
```

### 5.2 第一批格式

- JPG/JPEG；
- PNG；
- WebP；
- TIFF/GeoTIFF；
- 常见无人机导出的正射图或航拍图。

GeoTIFF 或带可用空间参考的文件可以自动给出初始覆盖范围；普通图片允许司令在地图上平移、缩放、旋转和调整透明度。第一版不做四角透视变形，以避免产生虚假的高精度感。

### 5.3 导入流程

```text
选择文件或填写允许目录路径
  → 校验格式、大小、路径和文件哈希
  → 读取图片元数据与采集时间
  → 判断是否存在空间参考
  → 进入地图覆盖模式
  → 平移、缩放、旋转、调整透明度
  → 填写来源、采集时间和备注
  → 保存为待确认影像层
  → 司令确认启用
  → 进入当前事件影像版本
```

浏览器不能直接读取任意本地路径，路径导入由本地服务端处理，限制在配置允许目录；原始文件不被修改，导入后复制到当前事件工作区。

每个影像版本记录：

```text
image_id
source_path
workspace_copy
file_hash
source_system
collected_by
collected_at
format
spatial_reference
coverage_transform
positioning_status
opacity
map_version
created_by
created_at
status
```

### 5.4 图片与正式态势关系

无人机图片是证据层，不自动变成火线或危险区。图片与正式标注不一致时：

```text
新影像到达
  → 产生差异提示
  → 生成待核验候选
  → 司令查看影像和正式对象
  → 转为正式标注 / 驳回 / 要求补查
```

不能静默移动正式火线。

### 6.2 标注字段

```text

kind
geometry

title
source
created_by

valid_from
valid_until
certainty
note
related_goal_id
related_plan_id
```

来源至少区分：

- 司令手动；
- 现场人员提交；
- 无人机影像；
- 外部系统；
- 后台候选；

### 6.3 标注状态

```text

```

```text

```

### 6.4 标注地图联动

点击标注后右侧显示来源、版本、依据、关联方案、关联命令和当前状态；点击右侧“定位地图”时打开所属图层、缩放至对象、短暂高亮并展开底部对象条。

## 7. 参谋指挥助手

### 7.1 前台定位

指挥助手在沙盘页右侧上方以常驻对话框出现；最小化后才退化为地图右下角玩偶入口。它不是普通聊天窗口，也不显示模型、Agent、推理链或技术运行状态。

前台显示的是业务结果：事实汇报、判断、信息缺口、收集申请、方案、决策请示、命令草案、执行回执、异常和核验结果。

### 7.2 组件层级

```text
advisor-panel
├── advisor-header
├── advisor-task-summary
├── advisor-thread
├── advisor-action-dock
└── advisor-composer
```

尺寸：

- 标题栏 44-48px；
- 任务摘要 60-76px；
- 消息区为主要剩余高度，独立滚动；
- 请示操作区 72-108px，有待处理事项时出现；
- 输入区 76-92px，固定在底部。

### 7.3 任务摘要

最多显示两行目标和计数：

```text
当前任务：保护东线村庄，控制火线越界
阶段：方案比较
已完成 3｜进行中 2｜待补查 1｜待决断 1
```

完整目标、约束、成功标准进入详情抽屉。

### 7.4 输入模式

```text
目标｜询问｜命令｜预案
```

- 目标：整理目标、优先级、约束和成功标准，等待司令确认；
- 询问：只读检索当前事实；
- 命令：形成命令草案，不直接下发；
- 预案：检查信息完整性后形成方案。

司令输入自然语言时，系统先生成结构化业务草案，不在参数不完整时猜测执行。

### 7.5 消息通用字段

```text
message_id
message_type
severity
created_at
updated_at
event_id
goal_id
task_id
status
body
source_label
source_version
related_object_ids
related_plan_id
related_order_id
expires_at
available_actions
```

前台消息必须显示类型、时间、正文、来源/数据时间、当前状态、关联对象和相关操作。

### 7.6 消息类型

| 类型 | 典型操作 |
|---|---|
| 事实汇报 | 查看依据、定位地图 |
| 判断汇报 | 查看依据、要求复核、申请补查 |
| 信息缺口 | 查看缺口、申请收集、按现有资料继续 |
| 信息收集申请 | 批准全部、部分批准、拒绝、暂缓、按现有资料继续 |
| 方案汇报 | 查看方案、地图推演、比较 |
| 决策请示 | 采纳、修改、否决、要求补查、暂缓 |
| 命令草案 | 编辑、确认、取消 |
| 执行回执 | 定位、查看证据、安排核验 |
| 异常报告 | 暂停、改令、重新研判、接受风险继续 |
| 核验结果 | 查看证据、接受结果、重新处理 |

### 7.7 消息状态

普通消息：

```text
生成 → 已送达 → 已查看 → 已归档
```

需要司令处理的消息：

```text
生成 → 待司令处理 → 已打开 → 处理中
  → 已批准 / 已拒绝 / 已部分批准 / 已转补查 / 已暂缓
  → 已归档
```

消息关闭不等于业务任务完成。消息可被标记为已过期、已替代或处理失败，但历史记录保留。

### 7.8 主动提醒

助手只在以下四类事项主动提醒：

1. 信息收集申请；
2. 待司令决断；
3. 命令异常或安全异常；
4. 关键执行回执或核验结果。

普通后台进展只增加未读点，不强制打断司令当前地图操作。

### 8.2 状态流转

```text
发现信息缺口
  → 待司令批准
  → 已批准全部 / 已批准部分 / 按现有资料继续 / 已拒绝 / 已暂缓
  → 等待数据
  → 数据到达
  → 数据校验
  → 形成观察/候选
  → 参谋重新研判
  → 信息缺口已关闭
```

“按现有资料继续”必须记录司令已知悉缺口并选择不再等待；受影响方案仍标注未确认前提。

没有真实外部接口时显示：

```text
已批准，等待人工导入无人机文件
```

不得伪造已自动获取或已发送。

### 9.3 默认方案生成

满足当前任务已确认、地图有关键态势对象、人员/资源信息可用且没有阻塞性事实冲突时，助手询问是否生成三套方案。

默认策略类型：

- A：北侧阻隔；
- B：东侧合围；
- C：保守防御与疏散。

参谋可以根据当前资料将某套标记为不适用，不得为了凑三套而硬编。每套方案必须有不同的目标取舍、力量配置、路线、资源、风险和停止条件。

### 9.4 方案状态

```text
未生成
→ 生成请求
→ 资料检查
→ 等待补充信息 / 等待核验
→ 生成中
→ 已形成
→ 已上图推演
→ 待司令决断
```

决断分支：

```text
待司令决断
├─ 采纳为决断基础
├─ 修改为新版本
├─ 要求补查
├─ 否决
├─ 暂缓
└─ 自提新方案
```

后续执行关联：

```text
决断草案 → 司令确认决断 → 命令准备 → 已形成命令
→ 执行中 → 待独立核验 → 已完成 / 部分完成 / 受阻 / 结果未知
```

终态：已否决、已替代、已暂缓、已过期、已失效、已完成、已取消。

### 9.5 方案版本规则

任何修改都生成新版本，不覆盖旧版本：

```text
A-v1：参谋首次生成
A-v2：司令修改后生成
A-v3：新影像到达后重新评估
```

方案记录父子关系、修改人、修改原因、修改字段、依据版本和地图对象差异。

已被决断或命令引用的方案不能直接编辑，只能生成新版本；新版本不改变已有决断或命令。

### 9.6 版本比较

最多同时比较两个版本或方案。比较内容分为：

1. 字段差异：策略、单位、路线、停止条件、资源需求、风险和未确认前提；
2. 地图差异：新增、删除、移动或范围变化对象。

差异颜色：

- 绿色：新增；
- 红色：删除/撤回；
- 蓝色：位置或范围变化；
- 灰色：未变化；
- 斜线：当前推演层；
- 虚线：上一版本推演层。

如果两个版本使用不同地图或影像版本，必须显示“基于不同数据版本，比较仅供参考”。

### 9.7 方案操作

| 操作 | 语义 |
|---|---|
| 查看地图 | 进入该方案推演，不采纳、不改变正式态势 |
| 详情 | 查看完整依据、资源、风险、停止条件和地图对象 |
| 比较 | 进入两个方案的字段/地图差异查看 |
| 修改 | 复制为新版本草稿 |
| 要求补查 | 针对未确认前提生成信息收集申请 |
| 采纳为决断基础 | 生成 GeneralDecision 草案，不下达命令 |
| 否决 | 记录原因并移入历史，不删除 |
| 自提方案 | 司令创建第四套或组合方案 |
| 退出推演 | 恢复正式态势视图，保留地图中心和上下文 |

## 10. 决断确认与执行联动

### 10.1 采纳与决断分两步

点击“采纳为决断基础”后，显示决断草案：

```text
目标
方案及版本
执行策略
执行区域
执行单位
接受的风险
不接受的风险
开始条件
停止条件
有效期
验收标准
未确认前提
```

司令确认前必须检查方案版本仍然有效、地图依据未变、无严重异常、单位和参数完整。确认界面必须明确：

```text
确认决断不等于自动下达外部命令。
```

确认后写入 `GeneralDecision`，参谋才可以准备 `ExecutionOrder`。

### 10.2 命令准备条件

- GeneralDecision 已确认；
- 执行单位和区域明确；
- 参数完整；
- 开始、停止、撤销条件明确；
- 验收标准明确；
- 方案依据未过期；
- 无未处理的严重阻塞；
- Policy 检查可以开始。

缺失时显示具体原因，禁止猜测补全。

### 10.3 命令拆解

参谋将命令拆为单位或个人任务，但先展示给司令确认：

```text
任务编号
执行单位/个人
行动内容
地图区域
开始条件
停止条件
所需资源
回执要求
验收标准
来源方案、决断和命令
```

真实通信/调度接口未接入时，只显示“任务已编制，待人工下达/待接入调度通道”。不得写“已发送给执行人”。

### 10.4 回执与地图

执行人通过现有网页登录提交接收、执行中、部分完成、完成、受阻、异常回执，可附位置、文字、图片或轨迹。

地图自动更新允许的过程状态：

- 已接收；
- 执行中；
- 回执位置；
- 最后已知位置；
- 受阻点；
- 回执时间。

执行人自报完成后进入“待独立核验”，不得直接变为已核验完成。

## 11. 方案回退与异常处理

### 11.1 不做破坏性回退

所有回退通过新版本或新决断完成，不删除历史、不覆盖旧命令。

- 未形成决断：从 A-v2 恢复内容生成 A-v3；
- 已确认决断、未形成命令：发起重新选择并形成新 GeneralDecision；
- 已形成命令、未执行：取消或替代旧命令后生成新命令；
- 已执行：暂停受影响任务、重新研判并走改令流程。

### 11.2 方案异常状态

| 异常 | 处理 |
|---|---|
| 方案生成失败 | 保留任务和资料，不产生半成品；显示原因并允许新请求重试 |
| 依据发生变化 | 标记“需重新评估”，暂时禁用采纳 |
| 引用对象被撤回 | 标记“依赖对象失效”，保留推演但禁止采纳 |
| 新影像与正式火线冲突 | 显示正式对象与候选边界对比，申请核验，不自动改线 |
| Policy 拒绝 | 业务方案保留，命令标记未获执行许可，显示规则原因 |
| 地图图层加载失败 | 方案文字可查看，地图操作禁用，显示地图不可用 |
| 版本冲突 | 当前编辑不覆盖新版本，要求查看差异后基于最新版本编辑 |
| 执行受阻 | 受影响任务冻结，相关区域橙色，进入暂停/改令/重新研判 |
| 结果未知 | 显示最后回执和最后已知位置，默认发起核验，不自动重试 |

### 11.3 异常等级

| 等级 | 示例 | 前台行为 |
|---|---|---|
| 提示 | 普通文件到达、低影响更新 | 未读点，不打断 |
| 需审批 | 信息收集、方案补查 | 黄色请示卡 |
| 受阻 | 道路受阻、单位无法到位 | 橙色异常，冻结受影响任务 |
| 严重 | 人员失联、火线越过保护边界 | 红色提示，主动展开并请示 |
| 结果未知 | 通信中断、回执不完整 | 灰紫色未知，先核验 |

异常关闭必须有处置结果、证据或司令明确接受风险；点击“已处理”不能直接关闭业务异常。

## 15. 按钮可用条件

| 按钮 | 可用条件 | 禁用原因示例 |
|---|---|---|
| 批准信息收集 | 待司令处理且当前会话有权限 | 已处理/无司令权限 |
| 部分批准 | 申请有多个可拆分收集项 | 不可拆分 |
| 按现有资料继续 | 存在开放信息缺口 | 无开放缺口 |
| 生成预案 | 当前任务已确认且无同任务生成中请求 | 目标未确认/生成中 |
| 查看地图 | 方案有有效推演对象 | 无空间对象/地图不可用 |
| 比较 | 至少两个可比较方案或版本 | 不足两个 |
| 修改 | 方案未锁定 | 已形成决断或已引用命令 |
| 采纳为决断基础 | 方案有效、可行、无严重阻塞 | 依据过期/依赖对象失效 |
| 确认决断 | 字段完整且司令确认 | 缺少单位/范围/停止条件 |
| 生成命令 | GeneralDecision 已确认 | 决断未确认 |
| 确认命令 | 参数完整、Policy/Approval 通过 | Policy 拒绝/参数缺失 |
| 暂停执行 | 命令执行中或结果未知 | 未开始/已结束 |
| 改令 | 原命令已暂停或异常需要改变范围 | 无改令理由 |
| 重新评估 | 依据变化或司令明确要求 | 无变化 |
| 否决方案 | 尚未进入不可逆执行动作 | 已形成不可撤销执行结果 |
| 关闭异常 | 已处置且有证据或司令接受风险 | 仍有未核验影响 |
| 接受风险继续 | 司令明确确认风险内容 | 非司令/风险未展示 |

按钮状态统一为：可用、处理中、成功、失败、禁用、已完成、已失效、需补充条件。点击后立即锁定，服务端结果返回后恢复或转为结果状态，不能依赖前端临时状态。

## 16. 开发分阶段建议

### P0：页面骨架和状态模型

### P3：指挥助手消息闭环

- 司令批准、部分批准、拒绝、暂缓和按现有资料继续；

### P4：方案生成、推演和版本比较

## 17. 验收主线

### 17.1 地图与标注

1. 打开沙盘首先看到真实本地地图，而非长表单；
2. 导入 JPG/PNG/WebP/TIFF 图片并完成粗略覆盖；
3. 影像来源、时间、粗略定位状态可见；
4. 司令绘制点、线、面，保存草稿并发布；
5. 发布态势与候选、推演层视觉区分；
6. 影像与正式火线冲突时只产生候选，不自动改线。

### 17.2 参谋与方案

1. 司令输入目标，系统生成目标草案并等待确认；
2. 参谋发现缺口，发出信息收集申请；
3. 司令批准、部分批准或选择按现有资料继续；
4. 新信息进入地图并影响相关方案状态；
5. 生成三套不同策略的方案；
6. 右下方案区显示摘要，点击方案切换地图推演；
7. 方案比较显示字段差异和地图差异；
8. 修改产生新版本，旧版本保留；
9. 否决需要原因且不删除方案。

### 17.3 决断与执行

1. 采纳方案只产生决断草案；
2. 司令确认后才形成 GeneralDecision；
3. 参数不完整时不能形成命令；
4. Policy/Approval 拒绝时业务方案仍保留，命令不能执行；
5. 命令拆解为执行人任务；
6. 执行人网页提交接收、进度、异常和完成回执；
7. 回执自动上图但先是观察层；
8. 独立核验通过后才进入已完成。

### 17.4 异常与审计

1. 执行受阻只冻结受影响任务；
2. 结果未知不自动重试；
3. 新信息使方案失效时禁用采纳并提示重新评估；
4. 版本回退通过新版本完成；
5. 关键状态流转均写入审计链；
6. 刷新、重载后状态、上下文和审计链一致。

## 附：第 19 章　方案时间轴推演与目标圈（V1.1 补，2026-08-26 用户对齐：方案一 + 目标圈作附加图例）

**目标**：方案卡从「摆布防草图」升级为「点开后图上出推演结果」，支撑司令看图判断。

**确定性规则（`impl/panda_brain/sand_sim.py`，纯函数只读）**
- 输入：已发布火线/火点（正式态势）+ 方案 `sim_shapes` 推演几何；无火源如实「推演暂不可用」，不编数。
- 预测火线：下风方位（演示常量：向东）平移 速率×时长；步长 T+2h / T+6h / T+12h，越远越淡；火点按全向最大蔓延半径画圈。
- 判定：火至时长 = 最近火距 ÷ 蔓延速率（120 米/时）；作业耗时 = 线长 ÷ 单队开通效率（60 米/时）；富余 ≥1h 来得及 / 0～1h 勉强 / <0 来不及。
- 目标圈（附加图例，由方案二并入）：火源质心 1000m 风险圈，圈内重点目标（水源/物资点/指挥部）标红；独立图层开关，与推演层同性质。

**前台呈现与红线**
- 方案卡增「推演结论：…（规则推演·非实测）」一行；「查看推演」同时叠加方案几何 + 三档预测火线，来不及的线段图上标红、勉强标橙；弹窗附火至/作业时长依据，悬停可查。
- 推演层永远是虚线叠加层，绝不写回正式火线/态势；公共屏不下发方案与推演载荷。
- 常量集中一处可调，口径文案（速率/效率/半径）随图例常驻展示，诚实标注非实测。

**后续可扩展（未入本批）**：多向蔓延各向异性、风场随时间变化、推演前提卡与「要求补查」联动（方案三形态）。
