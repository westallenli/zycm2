1. 背景与目标
表格
| 项目 | 说明 |
| 用户痛点 | 火情发生后，前线指挥部需30分钟内完成29个小组、200+人快速编组；原手工拉群、纸质签到平均耗时45分钟，错配率18%。 |
| 业务目标 | 把“从任务创建→人员到岗”时长压缩至10分钟以内，错配率<2%。 |
| 产品目标 | 提供“一键建任务、扫码入岗、自动权限”的闭环功能；支持离线缓存、断网续传。 |

2. 范围
In-Scope
任务新建、命名规则校验、二维码生成/导出/打印、扫码表单、人岗绑定、权限下发、日志审计。
Out-of-Scope
任务删除（本期只做“归档”）
二维码加密（放到v1.2）
3. 用户角色
表格
| 角色 | 说明 | 使用频次 |
| 指挥长（前线总指挥） | 创建任务并生成二维码 | 低（每场火1次） |
| 小组联络员 | 转发二维码、督促扫码 | 高 |
| 组员 | 扫码填报个人信息 | 高 |
| 系统管理员 | 查看扫码日志、补录人员 | 中 |

5. 非功能需求
表格
| 类别 | 要求 |
| 性能 | 二维码生成<500 ms；单任务最大1000人并发扫码，TPS≥50 |
| 兼容 | 微信内置浏览器、钉钉、Safari、Chrome内核≥80 |
| 安全 | 表单接口防刷：同一IP 1分钟≤10次，超过弹图形验证码 |
| 可靠 | 任务数据双写（PostgreSQL主库+副本），RPO≤5 min |
| 易用 | 表单首屏输入项≤5项，无需滑动即可提交 |

6. 原型 & 流程
（1）页面流转新建任务 → 二维码中心 → 扫码表单 → 提交成功页
（2）关键原型（文字线框）① 新建任务页┌─────────────────────────┐│ 任务名称* 〖20251130-西安-鄠邑区森林〗 ││ 起火时间* 〖日期时间组件〗 ││ 地点* 〖地图选点+反地理编码〗 ││ 【创建】 │└─────────────────────────┘
② 二维码中心顶部Tab：待扫码(12) | 已扫码(17)列表单元：扑救一组 | 应到8 | 实到5 | 【导出PNG】【打印】底部FAB：批量导出全部二维码
③ 扫码表单（H5）头像区：岗位图标+“扑救一组”表单区：姓名 | 职务 | 单位 | 手机号 | 是否队长【提交】
（3）时序图（核心）前端→后端：POST /task → 返回taskId前端→后端：POST /qrcode/batch → 返回29个url微信→后端：GET /qrcode/scan/{code} → 302到H5H5→后端：POST /person → 返回200 & permissionToken
7. 数据模型（核心字段）
表：taskid（PK, bigint）| name(varchar128) | fire_time(timestamp) | city(varchar32) | county(varchar32) | status(int) | creator_uid(varchar64) | ctime …
表：task_positionid | task_id(FK) | pos_code(varchar16) | pos_name | max_headcount(int) | current_count(int) | qrcode_url …
表：task_personid | task_id | pos_code | name | phone | unit | is_leader(bool) | gps | ctime …
唯一索引：task_id + phone，防止重复提交。
8. 接口清单（关键）
表格
| 接口 | 方法 | 说明 |
| /task | POST | 新建任务 |
| /task/{id}/qrcode | POST | 批量生成二维码 |
| /qrcode/export | GET | 下载PNG/PDF |
| /qrcode/scan/{code} | GET | 跳转H5 |
| /person | POST | 提交人员 |
| /permission/grant | POST | 下发权限 |

9. 验收方案
表格
| 场景 | 步骤 | 通过标准 |
| 正向流 | 新建→生成→扫码→提交 | ①到岗状态变绿②权限立即生效③日志可查 |
| 并发 | JMeter 100线程持续1 min | 成功率≥99%，平均响应<600 ms |
| 断网 | 关闭Wi-Fi填表单→恢复网络 | 数据自动提交，不丢失 |
| 异常 | 同一手机号重复提交 | 返回200但提示“已登记”，库中只保留1条 |
