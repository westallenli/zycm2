PRD-008 北斗短报文保底通信模块
版本：v1.0作者：产品经理-××创建日期：2025-12-03评审截止：2025-12-08需求来源：建设方案 §3.2（卫星通信保底）+ 省应急厅通信处北斗保障专题会议
1. 背景与目标
表格
复制
| 项目 | 说明 |
| 用户痛点 | ① “三断”极端场景下，前指与后方指挥中心完全失联；② 卫星电话占线高、费用高，不能群发；③ 救援队伍位置、伤亡、需求信息无法及时传出，影响二次增援。 |
| 业务目标 | 三断场景 30 min 内启用北斗；关键信息（坐标、人数、需求）后方收到率 ≥98%；单条通信费用 ≤0.3 元；报文端到端时延 ≤5 min。 |
| 产品目标 | 提供“一键发北斗→平台自动解析→GIS 落图→回执确认”的保底通信闭环；支持报文模板、压缩编码、流量管控、离线缓存。 |

2. 范围
In-Scope
北斗民用卡接入、报文模板、压缩编码、GIS 自动落图、回执管理、离线缓存、流量管控、费用统计。
Out-of-Scope
北斗 RDSS 语音对讲（v2.0）
北斗高精度定位（已含在单兵终端）

表格

| 后方值守员 | 平台接收、GIS 确认、回执 | 高 |
| 系统管理员 | 分配卡号、设置流量阈值 | 中 |

4. 功能需求（Story → AC）
表格
复制
| 编号 | 用户故事 | 验收标准（AC） | 优先级 |
| 4.1 | 作为通信员，我希望能一键检测北斗终端在线状态，确保信号良好。 | 1. 点击“北斗检测”返回：卡号、信号强度、剩余电量2. 信号≤2 格红色提示，≥4 格绿色3. 检测耗时 ≤10 s | P0 |
| 4.2 | 作为指挥长，我希望能通过模板一键发送“求救”报文，无需手工输入坐标。 | 1. 模板字段：时间、坐标、人数、伤情、需求类型2. 坐标自动读取单兵 GPS，精度≤10 m3. 发送确认弹窗：预计费用、字数、压缩后字节4. 点击“确认”后 30 s 内完成发送 | P0 |
| 4.3 | 作为平台值守员，我希望能自动解析北斗报文，并在 GIS 地图立即落图。 | 1. 解析成功率 ≥99%，错误报文进入人工队列2. 地图图标：红色=求救，蓝色=位置报告，绿色=任务完成3. 落图延迟 ≤60 s（含北斗传输） | P0 |
| 4.4 | 作为系统，我需在报文成功送达后自动回执，以便前端知晓。 | 1. 回执通过北斗返回到原卡号，内容：平台已收到+时间2. 前端收到回执后按钮变绿，提示“后方已收到”3. 若 5 min 无回执，自动重发 1 次 | P0 |
| 4.5 | 作为通信员，我希望能离线缓存未发报文，网络恢复后自动补发。 | 1. 本地缓存≥100 条，循环覆盖2. 缓存数据 AES-256 加密，密钥存在安全芯片3. 北斗信号恢复后自动补发，成功后本地删除 | P1 |
| 4.6 | 作为系统管理员，我希望能设置单卡日流量阈值，避免费用超支。 | 1. 默认 500 汉字/日（约 700 字节×50 条）2. 达到 90% 弹窗+短信预警，达到 100% 自动停发（可手动解封）3. 提供费用统计图表：日/周/月 | P1 |
| 4.7 | 作为指挥长，我希望能群发同一条报文给多张北斗卡，减少重复操作。 | 1. 支持多选卡号（最多 50 张）2. 群发后显示回执状态列表：绿色=已回执，灰色=待回执3. 失败卡号可一键重发 | P1 |
| 4.8 | 作为后方值守员，我希望能导出北斗通信日志，以便复盘。 | 1. 日志字段：卡号、时间、报文内容、费用、回执状态2. 支持按任务、时间段筛选3. 可导出 Excel/CSV | P2 |

5. 非功能需求
表格
复制
| 类别 | 要求 |
| 性能 | 单条报文发送 ≤30 s；50 条群发 ≤2 min |
| 兼容 | 支持北斗民用卡接口协议 4.0；兼容主流北斗终端（海格、华测、和星通） |
| 安全 | 报文 AES-256 加密，密钥 每月轮换；北斗卡号与白名单绑定 |
| 可靠 | 终端离线 30 天内缓存不丢失；平台收到报文双写（PostgreSQL+Redis），RPO≤1 min |

6. 原型 & 流程
（1）页面流转北斗检测 → 模板选择 → 编辑确认 → 压缩发送 → 平台解析 → GIS 落图 → 回执 → 日志导出
（2）关键线框① 北斗终端页信号：■■■■□ 80% 卡号：BDC01111 剩余流量：312 条【检测】【发送】【日志】
② 模板选择弹窗□ 求救 □ 位置报告 □ 任务完成 □ 自定义选择“求救”→自动带入坐标、时间、人数
③ 平台 GIS 落图图标红色闪烁，点击弹出：卡号 BDC01111 时间 14:32 人数 8 伤情 1 需求“饮用水+担架”
④ 回执列表群发 10 张卡：▇▇▇▇▇▇▇▇▇□ 90% 已回执 剩余 1 张未回执 【重发】
（3）时序图（核心）前端→终端：串口写入报文 → 终端→卫星 → 北斗地面站 → 平台网关 → 解析 → GIS → 回执 → 卫星 → 终端 → 前端更新状态
