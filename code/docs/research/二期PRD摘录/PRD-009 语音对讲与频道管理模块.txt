PRD-009 语音对讲与频道管理模块
版本：v1.0作者：产品经理-××创建日期：2025-12-04评审截止：2025-12-09需求来源：建设方案 §3.2/§3.4 语音融合需求 + 前线指挥部“吼群”调研纪要
1. 背景与目标
表格
复制
| 项目 | 说明 |
| 用户痛点 | ① 微信群语音延迟高、易漏接；② 多队伍同频道串台，指令混乱；③ 复盘时需回翻 60 分钟语音，无法检索。 |
| 业务目标 | 对讲延迟 ≤300 ms；频道冲突率 <2%；语音检索准确率 ≥90%；一键导出 5 分钟复盘音频 ≤30 s。 |
| 产品目标 | 提供“分层频道+一键对讲+限时回放+语音转写检索”的闭环；支持 Mesh/4G/北斗多链路自动切换、离线语音缓存。 |

2. 范围
In-Scope
分层频道、一键对讲、语音转写、限时回放、多链路切换、离线缓存、导出音频。
Out-of-Scope
与现有 PDT 数字对讲集群硬并网（v2.0）
实时语音翻译（v2.1）

5. 非功能需求
表格
| 类别 | 要求 |
| 性能 | 单频道 200 人在线，同时讲话 3 人，PTT 延迟 ≤300 ms |
| 兼容 | 支持 Android/iOS 原生 PTT 键、蓝牙耳机 MIC、Mesh 语音网关 |
| 安全 | 语音 AES-256 端到端加密，密钥每日轮换；频道号随机 8 位 |
| 可靠 | 语音双写（本地 SSD + 云端 OSS），RPO≤1 min；星标音频永久保存 |

6. 原型 & 流程
（1）页面流转频道列表 → 进入频道 → PTT 讲话 → 星标 → 语音搜索 → 导出音频
（2）关键线框① 频道列表├─ 前指频道（45 人）├─ 扑救一组（12 人）└─ 临时-空中支援（5 人）【30 min 后解散】
② 对讲页中间大按钮：按住讲话（红色）顶部：讲话人昵称滚动底部：【星标】【搜索】【导出】【更多】
③ 语音搜索输入“撤退”→结果：14:32 张三 置信度 0.92 【播放】14:35 李四 置信度 0.89 【播放】
④ 导出音频起止时间：14:30-14:35一键导出 → 生成 MP3 → 二维码下载
（3）时序图（核心）移动端→UDP/RTP：语音流 → 服务器 → 转码 → 实时转发服务器→转写 API：WebSocket → 返回文字 → 写入 Elasticsearch搜索→后端：POST /voice/search → 返回秒级时间戳 → 前端跳转播放
