PRD-005：离线通讯与断网续传模块
版本：v1.0作者：产品经理-××创建日期：2025-12-02评审截止：2025-12-07需求来源：建设方案 §3.2/§5.1 + 一线通信队访谈纪要
1. 背景与目标
表格
复制
| 项目 | 说明 |
| 用户痛点 | ① “三断”场景（断网、断路、断电）下指挥信息无法同步；② 浏览器/APP 重启后需重新填写；③ 现场与前线指数据不一致。 |
| 业务目标 | 三断场景 30 min 内恢复最低通信；数据同步丢失率 <1%；重启后操作续传成功率 ≥95%。 |
| 产品目标 | 提供“本地缓存 + Mesh 自组网 + 断网续传 + 重启续填”的闭环；支持二维码快传、极简中继、数据冲突自动合并。 |

2. 范围
In-Scope
本地缓存策略、Mesh 网络发现、数据碎片中继、断网合并、重启续填、冲突解决。
Out-of-Scope
卫星通信硬件选型（已固化）
语音对讲 QoS（v2.0）

4. 功能需求（Story → AC）
表格
| 编号 | 用户故事 | 验收标准（AC） | 优先级 |

| 4.3 | 作为指挥长，我希望能通过“中继节点”把指令传到 3 km 外断网小队。 | 1. 系统选择在线节点做跳点，最多 4 跳2. 延迟 ≤2 s/跳，丢包率 <3%3. 中继路径可视化，灰色=节点离线红色告警 | P0 |

5. 非功能需求
表格
| 类别 | 要求 |
| 性能 | Mesh 节点接入时延 ≤1 s；断网合并 1000 条记录 ≤3 s |
| 兼容 | 支持 OpenWRT-Mesh、BATMAN-adv v2023；浏览器 IndexedDB 主流全支持 |
| 安全 | 本地缓存 AES-256 加密，密钥存在 Secure Storage；二维码快传不含敏感坐标明文 |
| 可靠 | 节点离线 30 s 内被检测并切换中继；数据同步双校验（MD5+时间戳） |

6. 原型 & 流程
（1）页面流转网络检测 → 断网提示 → 本地填写 → 二维码快传/Mesh → 网络恢复 → 自动合并 → 冲突解决
（2）关键线框① 断网提示条┌──────────────────────────────┐│ ⚠ 网络已断开，数据将本地缓存       │└──────────────────────────────┘
② Mesh 拓扑页节点 4 信号 -52 dBm 带宽 12 Mbps┌─●──●──●─●┐└─▲-离线 30 s 告警
③ 冲突合并弹窗字段“到岗时间”存在 2 个版本：A) 14:32（本机） B) 14:35（服务器）【保留 A】【保留 B】【手动输入】
（3）时序图（核心）移动端→本地 DB：写入表单（离线）移动端→Mesh：POST /data/relay → 节点 B节点 B→前端指：WS /topic/sync → 存入临时队列网络恢复→后端：POST /sync/commit → 返回冲突列表 → 前端弹窗合并
7. 数据模型（核心字段）

9. 验收方案
表格
| 场景 | 步骤 | 通过标准 |
| 断网填报 | 关闭 Wi-Fi/4G 填写表单→恢复网络 | 数据自动提交，服务端与本地一致 |
| Mesh 中继 | 移除节点 A 的 4G，通过节点 B 跳转 | 指令到达延迟 ≤2 s/跳，丢包 <3% |
| 重启续填 | 填写 50% 表单→强制杀 APP→重启 | 自动恢复字段及图片，用户无需重填 |
| 冲突合并 | 两端同时修改“到岗时间”→恢复网络 | 弹窗提示冲突，合并后记录留痕 |
| 缓存上限 | 手工注入 500 MB 文件 | 达到上限弹窗，自动清理最早未同步文件，系统不死机 |
